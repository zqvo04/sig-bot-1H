## 0. 결론 요약

FP와 FN은 별개의 두 문제가 아니라 **하나의 원인이 만든 양면**이다.

2026-07-29 prior 재적합(개선안2)이 발행되면서 P̂의 스케일이 "전량 0.58~0.65"에서 **정직한 0.01~0.72 대역**으로 내려왔다. 캘리브레이션 자체는 옳은 방향이었다. 그런데 **`WRF_WIN_FLOOR = 0.58`을 아무도 같이 옮기지 않았다.** 플로어는 2.3배 낙관적이던 구(舊) P̂ 스케일에 맞춰 정해진 숫자였고, P̂만 정직해지자 두 가지가 동시에 일어났다.

| | 기전 | 실측 |
|---|---|---|
| **FN (구조적)** | 6셋업 중 **BO를 뺀 전부가 P̂ 도달 상한 < 플로어**. 후보 품질과 무관하게 발사가 원천 봉쇄됐다. | RV의 P̂ 최댓값 **0.408**, TC 0.253, TF 0.231, BR 0.267 — 전부 floor 0.58 미만. 테이블 발행 이후 **후보 62건 → 라이브 발사 0건**. |
| **FP (잔존)** | 플로어를 넘는 유일한 셋업(BO) **내부에서는 P̂의 변별력이 0**. 어느 BO를 쏠지는 사실상 무작위. | 셋업내부 AUC(P̂) = **0.490**. 반면 셋업 base-rate AUC = **0.698**. |

즉 발사판정 `P̂ ≥ W_floor`는 확률 게이트의 외피를 쓴 **셋업 화이트리스트**로 퇴화했다. 화이트리스트는 셋업 순서를 맞추는 데는 성공했지만(base-rate AUC 0.698), 그 안에서 옥석을 가리는 일은 전혀 못 한다.

그리고 이 실패가 검증을 통과한 이유가 따로 있다 — **재적합 승격 조건이 Brier 단독**이었다. Brier는 레벨(평균) 보정만으로 0.3612 → 0.1503으로 극적으로 좋아지고, 그동안 순위정보(AUC)는 0.49에 머물러 있었다. **게이트가 볼 수 없는 축에서 실패가 일어났다.**

## 1. 측정 방법

### 1-A. 왜 JSONL의 `fire` 플래그를 그대로 쓰면 안 되는가

JSONL의 `fire`는 **수집 당시 config**의 산물이다. 관측 구간(6/17~8/1) 동안 `WRF_SHADOW_SETUPS`에 TF 추가, `WRF_PRIOR_REFIT_ENABLED` 점등, 보정 테이블 재발행이 모두 일어났다. 기록된 플래그로 집계하면 서로 다른 세 개의 로직을 한 통에 섞는다.

→ 진단은 전부 **재채점(rescore)** 기준이다: 저장된 후보의 `C/L/F/ctx/rr`에 **현행 config + 현행 테이블**로 `calibration.evaluate` → EV 게이트 → 격리 판정을 다시 돌린다.
한계: L2(디텍터) 단계는 재실행할 수 없다(원본 `measures`/`ohlcv` 미보존). 즉 **후보 집합 자체는 수집 당시 디텍터의 산물**이고, 재채점은 L3/L4 게이트만 현행화한다. 이 한계는 아래 모든 결론에 적용된다.

### 1-B. 표본

```
결판 337건 · 전체 승률 0.223 · 평균 RR 2.01 · 손익분기 승률 1/(1+RR) = 0.333
탈중첩(stride 24h) 174건 · 승률 0.276
반기 분할  H1(6/17~7/13) n=167 승률 0.287 | H2(7/13~8/1) n=170 승률 0.159
```

**전체 후보 모집단의 무조건부 엣지는 −0.11(0.223 − 0.333)로 깊게 음수다.** 이 위에 어떤 랭커를 얹든, 랭커가 실제 순위정보를 가져야만 양수가 나온다.

## 2. 증거

### 2-A. 라이브가 멈췄다 (Q0)

| 주 | 후보 | 발사 | P̂ 평균 |
|---|---|---|---|
| 2026-W28 | 70 | 7 | 0.362 |
| 2026-W29 | 108 | 11 | 0.397 |
| 2026-W30 | 124 | 17 | 0.440 |
| 2026-W31 | 104 | 8 | 0.301 |

**보정테이블 발행(7/29 11:56) 이후: 후보 62건 → 발사 0건.**
337 결판 전체를 현행 로직으로 재채점하면 **발사 7건 / 4.8주 = 1.5건/주(3심볼)**, 전량 `BO long`.

목적함수 `max N s.t. WinRate ≥ W_floor`(5-A)에서 N이 사실상 0으로 붕괴했다. FP는 "발사를 안 함"으로 해결됐고, 그 대가가 FN 전면화다.

### 2-B. 게이트 퍼널 (Q1)

| 귀속 사유 | n | 승률 | RR | 손익분기 | **edge** | sumR | avgR |
|---|---|---|---|---|---|---|---|
| 격리:SHADOW_SETUP | 226 | 0.146 | 2.00 | 0.333 | **−0.187** | −127.96 | −0.566 |
| FLOOR | 80 | 0.350 | 1.97 | 0.337 | **+0.013** | +1.49 | +0.019 |
| 격리:FIRE_RIGHTS | 24 | 0.375 | 2.18 | 0.315 | **+0.060** | −3.75 | −0.156 |
| FIRE | 7 | 0.714 | 2.01 | 0.332 | +0.382 | +8.35 | +1.192 |

읽는 법:
- **격리(섀도 셋업)는 제대로 작동한다.** edge −0.187, 226건 −128R을 정확히 차단했다. 거버넌스 장치는 유일하게 성공한 부품이다.
- **FLOOR가 막은 80건의 edge는 +0.013 — 즉 플로어는 손익분기 근방의 집단을 통째로 잘라내고 있다.** 이것이 FN의 본체다.
- VETO 귀속 0건, EV/RR 귀속 0건 — 두 게이트는 이 표본에서 아무것도 거르지 않았다(플로어가 먼저 다 잘라서 도달하지 못한다).

### 2-C. 셋업별 P̂ 도달 상한 (Q1) — 구조적 FN의 직접 증거

| setup | n | P̂ 중앙 | **P̂ 최댓값** | floor | 발사 | 도달 가능? |
|---|---|---|---|---|---|---|
| BO | 34 | 0.599 | 0.661 | 0.58 | 7 | ✅ |
| RV | 76 | 0.099 | **0.408** | 0.58 | 0 | ❌ |
| BR | 141 | 0.134 | 0.267 | 0.58 | 0 | ❌ |
| TC | 59 | 0.203 | 0.253 | 0.58 | 0 | ❌ |
| TF | 26 | 0.174 | 0.231 | 0.58 | 0 | ❌ |
| MR | 1 | 0.261 | 0.261 | 0.58 | 0 | ❌ |

**RV는 아무리 좋은 후보여도 발사가 불가능하다.** 재적합 절편 `b0[RV] = −0.6028`에 기울기가 `wC=0.322 / wL=0.059 / wF=0.0`이므로 C=L=F=1(이론상 최댓값)이어도 z = −0.22 → P̂ = 0.445 < 0.58이다. 이는 확률적 탈락이 아니라 **대수적 불가능**이다.

부차 확인: min-axis 소프트 페널티(λ=2.5)는 후보의 70.6%에 걸리고 RV 중앙 P̂을 0.330 → 0.099로 더 눌렀지만, **페널티를 완전히 제거해도 플로어 통과 후보 수는 27건으로 동일**하다. 즉 페널티는 FN의 원인이 아니라 증폭기이며, 원인은 절편-플로어 스케일 불일치다. (다만 λ는 구 로그오즈 스케일에 맞춰 정해진 값이 새 절편 위에 그대로 쌓인 것이라 **이중 차감**이며, 순위 해상도를 더 뭉갠다.)

### 2-D. P̂의 변별력 분해 (Q4)

```
전체 AUC(P̂)          = 0.550
셋업내부 AUC(P̂ 랭크) = 0.490   ← 셋업을 고정하면 정보 0 (동전던지기)
셋업 base-rate AUC   = 0.698   ← 변별력의 실제 출처는 전부 여기
```

**P̂의 정보량은 100% 셋업 절편에서 나오고, C/L/F가 기여하는 셋업내부 순위는 0이다.**

축 IC의 셋업별 이질성이 그 이유다:

| setup | n | 승률 | AUC(C) | AUC(L) | AUC(F) |
|---|---|---|---|---|---|
| BO | 34 | 0.500 | 0.536 | **0.417** | 0.415 |
| BR | 141 | 0.184 | **0.422** | 0.473 | 0.495 |
| RV | 76 | 0.316 | **0.661** | 0.608 | 0.613 |
| TC | 59 | 0.119 | 0.398 | **0.766** | 0.220 |

C는 RV에서 0.661(강한 양), BR/TC에서 0.40~0.42(음). L은 TC에서 0.766, BO에서 0.417. **축의 부호가 셋업마다 뒤집힌다.** `prior_logodds = b0[setup] + wC·C + wL·L + wF·F`는 **셋업 공통의 단일 기울기**를 강제하므로 이 구조를 표현할 방법이 없다. 게다가 재적합에는 부호제약(w ≥ 0)이 걸려 있어, 상충하는 셋업들 사이에서 최적해는 "기울기를 전부 0 근처로 보내는 것"이 된다.

반기 안정성도 없다:

| | base | AUC(P̂) | AUC(C) | AUC(L) | AUC(F) |
|---|---|---|---|---|---|
| H1 | 0.287 | 0.626 | 0.548 | 0.689 | 0.464 |
| H2 | 0.159 | **0.438** | 0.312 | 0.497 | 0.678 |

**세 축 모두 반기 사이에 부호가 뒤집힌다.** 현 표본에서 축 가중치를 적합하는 행위 자체가 잡음 적합이다.

### 2-G. 기하로는 못 고친다 (부록 스윕)

같은 진입·방향에 SL 배수(×0.75~2.0)와 RR(0.75~3.0)만 바꿔 20조합을 재채점했다.

| | 전체 풀 edge | 비섀도 풀 edge |
|---|---|---|
| 20조합 전부 | **−0.068 ~ −0.236 (전 격자 음수)** | −0.194 ~ **+0.127** |
| 최선 셀 | 없음 | sl×2.0, RR 0.75~1.0 → 승률 0.63~0.69, avgR +0.09~+0.14 |

- **전체 후보 풀은 어떤 TP/SL 조합으로도 손익분기를 못 넘는다.** FP는 기하 문제가 아니라 방향(진입) 문제다. → 2026-07 문서의 개선안4(TP 기하 재설계)는 **이 데이터로는 지지되지 않는다**. 이미 `WRF_TP_MFE_CAP=true`로 켜져 있는데, 그 효과의 상한이 여기 있다.
- 비섀도(BO/RV/MR) 풀은 **넓은 SL × 가까운 TP**(RR<1)에서만 승률 0.58 플로어를 실제로 넘긴다(0.639 / 0.693). 이는 아래 §5 Fork A의 근거가 된다 — 단, avgR은 +0.09 수준으로 얇고 좌측 꼬리가 두꺼운 프로파일이라 권장이 아니라 **선택지**로만 제시한다.

### 2-H. 대조군: 축을 버리고 base-rate만 쓰면 (부록 워크포워드)

각 후보 시점 이전(+72h embargo)의 결판만으로 `(setup, dir)` Beta-Binomial 수축 승률을 추정 — look-ahead 없음.

```
AUC(p_wf, setup×dir base-rate) = 0.620      AUC(P̂ 현행) = 0.488
  H1: p_wf 0.556 / P̂ 0.540
  H2: p_wf 0.657 / P̂ 0.438   ← P̂은 뒤집히고, base-rate는 유지된다
```

**C/L/F 3축 + 재적합 + δ_eff 전 스택을 합친 P̂보다, "셋업×방향 과거 승률" 한 줄이 더 잘 맞고 더 안정적이다.** 특히 H2(레짐이 어려워진 구간)에서 P̂은 AUC 0.438로 역전되는데 base-rate는 0.657로 버틴다.

| **RC2** | **표현력 부족** — 단일 pooled 기울기 + 부호제약으로는 축 부호가 셋업마다 뒤집히는 구조를 담을 수 없다. | §2-D | 셋업내부 AUC 0.490 → BO 내부 FP가 무작위로 발생 |

| **RC4** | **검증 메트릭 실패** — 재적합 승격 조건 `improved`가 **Brier 단독**. Brier는 레벨 보정만으로 0.3612→0.1503이 되고, 그동안 AUC는 0.49로 정지. 순위정보 붕괴를 게이트가 볼 수 없었다. 또한 홀드아웃이 단순 꼬리분할이라 **72h embargo가 없어 경계 누수**가 있다. | `prior_refit_diagnostics`, §2-D | 실패한 모델이 자동 승격돼 라이브에 반영 |

**한 문장**: FP/FN 잔존의 원인은 게이트 임계 튜닝이 아니라, **정직해진 확률 스케일과 옛 플로어가 어긋난 채 배선됐고(RC1), 그 확률이 셋업 이름 말고는 아무 정보도 담고 있지 않다는 사실(RC2·RC3)을 검증 메트릭이 감추었다(RC4)** 는 것이다.

### 개선안 1 — 발사 임계를 "절대 승률"에서 "손익분기 상대"로 재정의 (신규 파라미터 0개)

| 항목 | 내용 |
|---|---|
| **1. 대상** | `src/wrf/engine.py`(발사판정), `src/config.py`(`WRF_WIN_FLOOR` 의미), `src/wrf/calibration.py`(floor 반환) |
| **2. 현재 문제** | `P̂ ≥ 0.58`은 RR≈1을 암묵 가정한 임계다. 현행 평균 RR 2.01에서 손익분기 승률은 0.333이고, 0.58은 트레이드당 EV +1.15R을 요구한다. 재적합으로 P̂이 정직해지자 이 임계가 5셋업을 대수적으로 봉쇄했다. |
| **3. 근거** | §2-C(RV의 P̂ 상한 0.408 < 0.58, C=L=F=1이어도 0.445), §2-A(발행 후 62후보 0발사), §2-B(FLOOR가 막은 80건의 edge +0.013) |
| **4. 방향** | 발사 조건을 `P̂ ≥ W_floor`에서 **`P̂ ≥ (1 + EV_MIN)/(1 + RR)`** 로 바꾼다. 이는 이미 코드에 있는 EV 게이트(`WRF_EV_GATE`, `WRF_EV_MIN=0.15`)를 **부등식의 좌변이 아니라 임계 자체**로 승격하는 것이며, 신규 파라미터가 없다(5-K 준수). 판정은 여전히 단일 부등식이고 점수 합산이 아니다(5-J 준수). |
| **5. 로직** | **(a)** `engine.run_engine`: `fire = p_hat >= floor ∧ …` 를 `fire = ev >= WRF_EV_MIN ∧ rr >= WRF_EV_RR_FLOOR ∧ …` 로 교체(플로어 조건 제거). 토글 `WRF_FLOOR_MODE = "winrate"(기본, 무변경) | "ev"`. <br>**(b)** `WRF_WIN_FLOOR`는 폐기하지 않고 **보정셀의 사후검정 기준**(`fire_rights`의 `p_wr_ge_floor`)으로만 남긴다 — 거버넌스 의미는 유지, 발사 의미만 이관. <br>**(c)** 사이징 `_size_from_p`의 기준점도 같은 임계로 이동(현재는 floor 기준 선형). |
| **6. 기대 효과** | 재채점 기준 발사 **7건 → 32건**(비섀도, EV_MIN=0.15), 승률 0.406, sumR +1.44. 주당 1.5건 → **약 6건**. RV short(edge +0.067) 봉쇄 해제. |
| **7. 부작용 / 위험** | ① **엣지를 만들어내지 않는다.** 위 32건의 반기 분할은 H1 avgR +0.531 / **H2 −0.384**로, 최근 구간에서는 여전히 음수다. 빈도만 복구된다. ② RR을 부풀리면 임계가 낮아지므로 **RR 인플레이션에 취약**해진다(2026-07 문서가 지적한 BO의 SL 타이트닝 문제와 정확히 결합) — `WRF_EV_RR_FLOOR`와 `WRF_BO_SL_NEAR` 페널티가 방파제이며, 이 둘의 실효성을 함께 감시해야 한다. ③ "승률 ≥ 플로어" 공표가 사라지므로 Notion/README 문구를 EV 기준으로 바꿔야 한다. |
| **8. 과적합** | **낮음.** 임계를 데이터에 맞추는 게 아니라 **RR과 정합시키는 항등식**이다. 자유도 0(EV_MIN은 기존 값 재사용). 다만 EV_MIN을 튜닝 노브로 쓰기 시작하면 즉시 중간 위험이 된다 — **0.15 고정, 단독 튜닝 금지**를 규약으로 박는다. |
| **9. 검증** | ① `diagnose_fp_fn.py`에 `--floor-mode ev` 추가 → 발사수·승률·avgR·edge를 **반기 2분할 × 방향별**로 보고. ② Gate-In: 두 반기 모두에서 발사집합 edge ≥ 0(현 표본에선 H2가 음수이므로 **지금 켜면 안 된다** — §6 참조). ③ 4주 그림자 병행(`shadow_band` 기록 활용) 후 점등. |

### 개선안 2 — 재적합 승격 조건을 Brier 단독에서 "AUC + embargo 홀드아웃"으로 (RC4 수리)

| 항목 | 내용 |
|---|---|
| **1. 대상** | `analysis/calibrate.py::fit_prior_refit` / `_prior_score`, `src/config.py`(`WRF_PRIOR_REFIT_*`) |
| **2. 현재 문제** | `improved = brier_refit < brier_config` 하나로 계수가 라이브에 승격된다. Brier는 **레벨(평균) 오차가 지배**하므로, 순위정보가 0이어도 평균만 맞추면 극적으로 개선된다. 실제로 0.3612 → 0.1503(−58%)이었는데 AUC는 0.49였다. 홀드아웃도 단순 꼬리분할이라 경계에서 72h 라벨 중첩이 새어든다. |
| **3. 근거** | `prior_refit_diagnostics`(brier 0.3612→0.1503, AUC 미측정), §2-D(전체 AUC 0.550 / 셋업내부 0.490), §2-E(ridge 하나로 계수가 0.188↔0.000) |
| **4. 방향** | 승격 조건을 **다중 조건 AND**로 바꾸고, 실패 시 **기울기만 0으로 발행**한다(절편은 살린다 — 절편은 base-rate라 정보가 있다). 예측 로직 변경이 아니라 **발행 게이트 변경**이므로 라이브 무학습 원칙(5-B) 불변. |
| **5. 로직** | **(a)** `_prior_score`에 **AUC**와 **셋업내부 AUC**(셋업별 랭크 정규화 후 산출)를 추가. <br>**(b)** 홀드아웃 경계에 `WRF_EMBARGO_HOURS`(72h)를 실제로 적용 — train 마지막 라벨의 exit + 72h 이후 행부터 holdout. <br>**(c)** 승격 조건: `brier 개선 ∧ AUC_holdout ≥ WRF_REFIT_AUC_MIN(0.55) ∧ 셋업내부 AUC_holdout ≥ 0.55`. <br>**(d)** 미충족 시 `wC=wL=wF=0`으로 발행(= 순수 셋업 base-rate 모델). 이는 **현 표본에서 가장 정직한 모델**이다(§2-H: base-rate 단독 AUC 0.620 > 현행 P̂ 0.488). <br>**(e)** 진단 블록에 `auc_refit / auc_within_setup / n_holdout_after_embargo`를 항상 기록. |
| **6. 기대 효과** | 잡음 기울기가 라이브에 도달하지 못한다. 현 표본을 재발행하면 (c)를 통과하지 못하므로 **기울기 0 + 셋업 절편**이 발행된다 → P̂이 "정직한 셋업 base-rate"가 되고, 개선안 1의 EV 임계와 결합하면 셋업 단위 EV 판정이라는 **해석 가능한 상태**가 된다. |
| **7. 부작용 / 위험** | ① 기울기 0이면 셋업내부 순위가 완전히 사라진다 — 지금도 실질 0이므로 손실은 아니지만, "P̂이 후보를 고른다"는 서사가 명시적으로 폐기된다. ② AUC 임계(0.55)가 새 노브다 — 그러나 방향은 "발행을 어렵게" 하는 쪽이라 과적합 위험이 낮다. ③ embargo 적용으로 홀드아웃 표본이 줄어 진단력이 떨어진다(현 337건 기준 92 → 약 60~70 추정). |
| **8. 과적합** | **낮음.** 적합 절차가 아니라 승격 문턱을 높이는 변경. 실패 시 폴백이 **더 단순한 모델**이라는 점이 안전판이다. |
| **9. 검증** | ① 과거 테이블을 재생성해 새 게이트가 **현행 발행분을 기각하는지** 확인(항등 케이스의 반대 — 반드시 기각돼야 한다). ② 기울기 0 발행본으로 §2-H의 워크포워드 AUC를 재현. ③ Gate-Out: 다음 주간 잡의 진단 블록에 `auc_within_setup`이 기록되고, 승격/기각 사유가 로그에 남는다. |

### 개선안 3 — 재적합 학습 모집단을 "발사 가능 후보"로 한정 (RC3)

| 항목 | 내용 |
|---|---|
| **1. 대상** | `analysis/calibrate.py::fit_prior_refit`(입력 `dec` 필터), `src/config.py` |
| **2. 현재 문제** | 결판 337건 중 **226건(67%)이 섀도 셋업**이다. 라이브가 절대 쏘지 않는 후보가 pooled 기울기를 다수결로 결정한다. |
| **3. 근거** | §2-E — 전량 적합 `wC=0.009/wL=0/wF=0` vs 비섀도 적합 `wC=0.327/wL=0.099/wF=0.090`. 같은 데이터·같은 ridge인데 기울기 부호와 크기가 통째로 바뀐다. |
| **4. 방향** | **기울기(공통 파라미터)는 발사 가능 모집단에서만** 적합한다. **절편(셋업별 base-rate)은 전량**에서 적합한다 — 섀도 셋업도 자기 절편은 자기 데이터로 추정해야 복권 심사가 가능하다. 즉 "공유 파라미터는 발사 가능 집단이, 고유 파라미터는 각자가" 원칙. |
| **5. 로직** | `fit_prior_refit(dec)` → `fit_prior_refit(dec, slope_mask = ~dec.setup.isin(WRF_SHADOW_SETUPS))`. IRLS에서 기울기 열의 gradient·Hessian 기여를 mask 행으로 제한(2단계 적합: ① 전량으로 절편 초기화 → ② mask 행으로 기울기만 갱신). 토글 `WRF_REFIT_SLOPE_LIVE_ONLY`(기본 OFF). |
| **6. 기대 효과** | 발사 가능 후보에서 실제로 존재하는 축 신호를 기울기가 회수할 수 있다. 단 개선안 2의 AUC 게이트를 **통과해야만** 발행되므로, 이 안 단독으로는 라이브가 바뀌지 않는다(안전). |
| **7. 부작용 / 위험** | ① 발사 가능 모집단이 작다(111건) → 분산이 커지고 ridge 의존이 더 심해진다. ② 섀도 셋업이 복권되면 모집단이 바뀌어 기울기가 점프한다 — **복권 시 기울기 재적합을 강제**하는 규약이 필요. ③ 선택편향: 발사 가능 집단은 이미 게이트를 통과한 집단이라 절단된 분포다. |
| **8. 과적합** | **중간.** n=111에 3기울기는 여전히 얇다. 완화: 개선안 2의 AUC 게이트가 그대로 적용되고, 미달 시 기울기 0 폴백이므로 **잘못될 때의 결과가 "현상 유지"** 다. |
| **9. 검증** | ① 두 모집단 각각의 계수·홀드아웃 AUC를 나란히 보고(이미 `--` Q5로 출력). ② 부트스트랩(블록 부트스트랩, 블록=72h)으로 계수 신뢰구간을 산출해 **0을 포함하는지** 명시. 포함하면 발행 금지. |

### 개선안 4 — min-axis 페널티를 재적합 스케일에 맞춰 재도출 (이중 차감 제거)

| 항목 | 내용 |
|---|---|
| **1. 대상** | `src/wrf/calibration.py::_min_axis_penalty`, `src/config.py`(`WRF_PRIOR_MIN_AXIS_LAMBDA`) |
| **2. 현재 문제** | λ=2.5는 **구 prior의 로그오즈 스케일**(b0 −0.15~−0.95, 기울기 1.1/1.3/1.2, cap 0.65)에서 "약한 축을 매끄럽게 감점"하도록 정해진 값이다. 재적합 후 기울기가 1/4~1/20로 줄었는데 페널티만 원래 크기로 남아, **감점이 신호보다 커졌다**. |
| **3. 근거** | §2-C 부차확인 — 페널티가 후보의 70.6%에 걸리고 RV 중앙 P̂을 0.330 → 0.099로 누른다. 반면 페널티를 제거해도 플로어 통과 수는 27건으로 불변 → **FN의 원인은 아니지만 순위 해상도를 뭉개는 순수 손실**이다. |
| **4. 방향** | 페널티를 **절대 상수가 아니라 기울기에 비례**하도록 재정의: `λ_eff = λ_ratio × (wC + wL + wF)`. 재적합이 기울기를 줄이면 페널티도 같은 비율로 줄어 스케일 정합이 자동 유지된다. 기존 기본값(config 기울기 합 3.6, λ=2.5)을 보존하는 `λ_ratio ≈ 0.69`가 되돌리기 가능한 기본값이다(5-K③). |
| **5. 로직** | `_min_axis_penalty(C,L,F, coefs)` 로 시그니처 확장, `λ_eff` 계산. 토글 `WRF_MIN_AXIS_SCALED`(기본 OFF = 현행 상수). |
| **6. 기대 효과** | 재적합 스케일에서 페널티가 신호를 압도하지 않는다. 셋업내부 순위 해상도 일부 회복(측정 필요 — 회복량은 미지). |
| **7. 부작용 / 위험** | ① 기울기가 0으로 발행되면 페널티도 0이 되어 **역행 축(음수 C/L/F) 차단이 사라진다** — 이 경우 min-axis를 하드 precond로 되돌릴지 별도 판단이 필요하다. ② 페널티 약화는 저품질 후보의 P̂을 올려 FP를 늘릴 수 있다. |
| **8. 과적합** | **낮음.** 스케일 정합 항등식이고 새 자유도는 λ_ratio 1개인데 기존 동작을 보존하는 값으로 고정 출시. |
| **9. 검증** | ① 페널티 ON/OFF/스케일 3안의 셋업내부 AUC를 비교 — 개선이 없으면 채택하지 않는다. ② 음수 축 후보의 실현 승률을 별도 집계해 "페널티가 실제로 나쁜 후보를 걸렀는지" 확인(현재는 미검증 가정이다). |

### 개선안 5 — 빈도 회복은 유니버스 확장으로 (5-A 준수)

| 항목 | 내용 |
|---|---|
| **1. 대상** | `src/config.py`(심볼 유니버스), 데이터 수집 잡 |
| **2. 현재 문제** | 3심볼 × 1H로 주당 발사 1.5건. 개선안 1을 켜도 약 6건이다. 보정 셀 공간은 6셋업 × 4레짐 × 3거시 = 72셀인데, 셀당 유효 표본이 연 단위로도 두 자리를 못 채운다 — **폐루프(발사권·δ_eff)가 물리적으로 학습할 수 없는 속도**다. |
| **3. 근거** | §2-A, 그리고 `calibration_table.json`의 `n_cells=28 / n_shadow=1` — 6주 누적으로 강등 판정이 가능한 셀이 손에 꼽는다. |
| **4. 방향** | 플로어를 낮춰 N을 늘리는 것은 설계 위반(5-A)이다. **유니버스 확장**이 정공법이다. 심볼 수를 늘리면 셀당 표본이 선형 증가하고, 심볼 간 상관이 1이 아니므로 유효 표본은 명목보다 덜 손해본다. |
| **5. 로직** | 수집·엔진 루프는 이미 심볼 반복이고 각 심볼이 `try/except`로 격리돼 있다(5-F) — **코드 변경 없이 유니버스 리스트만 확장**된다. 단 ① 백분위 윈도(200봉) 워밍업이 심볼마다 필요, ② 거래량/스프레드 하한으로 유동성 필터가 필요(VETO ①이 이미 스프레드를 본다), ③ JSONL 용량이 심볼 수에 비례(현재 심볼당 7.3MB/6주). |
| **6. 기대 효과** | 심볼 10개면 발사 빈도 ~3.3배, 셀 표본 ~3.3배 → 발사권 폐루프가 실제로 돌기 시작한다. 승률 플로어는 불변(5-A의 정확한 처방). |
| **7. 부작용 / 위험** | ① 저유동성 알트는 슬리피지·청산 캐스케이드 리스크가 다르다 — 유동성 필터 없이 확장하면 새로운 FP 원천이 된다. ② 심볼 간 상관(알트는 BTC 베타가 높다)으로 **유효 표본 증가는 명목보다 작다** — exret(BTC초과) 라벨로 검증해야 착시를 피한다. ③ 리소스(API rate limit, JSONL 용량, 잡 실행시간). |
| **8. 과적합** | **없음** (모델 변경 아님). 다만 유니버스 선정 자체가 사후 선택이 되지 않도록 **선정 기준을 먼저 문서화**(예: 거래대금 상위 N, 상장 경과일 ≥ X)하고 그 기준으로 기계적으로 뽑는다. |
| **9. 검증** | ① 확장 전후 셀당 `n_indep` 증가율. ② 신규 심볼의 첫 4주는 **섀도로만** 운영(발사권 미부여) 후 편입 — 5-I 그대로. ③ 원시수익과 exret 양쪽으로 코호트 성과 보고. |

## 5. 설계 원칙 충돌 — 결정이 필요한 지점

### Fork A. `W_floor`의 의미 (5-A와 직결)

5-A는 "승률은 보정이 보장한다 — 임계 = 플로어"라고 정의한다. 그런데 **평균 RR 2.01에서 승률 0.58은 경제적으로 요구할 이유가 없는 수치**다(손익분기 0.333). 세 갈래가 있고, 셋 다 일관된 설계다.

| | 내용 | 실측 근거 | 결과 |
|---|---|---|---|
| **A1 (권고)** | 플로어를 **EV 기준**으로 재정의(개선안 1). 승률 플로어는 거버넌스(발사권 사후검정)에만 남긴다. | 발사 7 → 32건, 승률 0.406 | 5-A의 문구는 바뀌지만 **의도(엣지 보장)는 보존** |
| **A2** | 승률 플로어 0.58을 **지키고 기하를 바꾼다** — SL ×2.0, RR 0.75~1.0. 비섀도 풀 승률 0.63~0.69로 실제로 플로어를 넘긴다. | §2-G, avgR +0.09~+0.14 | 5-A 문구 유지. 대신 **얇은 이익 / 두꺼운 좌측 꼬리** 프로파일이 되고, 개선안 1·4가 불필요해진다 |
| **A3** | 현상 유지 | 발사 0~1.5건/주 | 5-A의 N 항이 붕괴 — 사실상 봇 정지 |

**권고는 A1**이다. A2는 승률 숫자를 만족시키지만 avgR +0.09는 수수료·슬리피지(로그 미반영)를 넘기 어렵고, RR<1은 한 번의 손실이 여러 번의 이익을 지우는 구조라 표본이 적을 때 판정 자체가 어려워진다. 다만 **A2를 배제할 근거도 데이터에는 없다** — 승률 기준을 문자 그대로 지키는 것이 목적이라면 유일하게 실현 가능한 경로다.

### Fork B. 방향 비대칭 (5-D)

§2-H는 `(setup, dir)` base-rate가 현행 P̂보다 강하고 안정적임을 보인다(AUC 0.620 vs 0.488). 그러나 5-D는 "모든 디텍터·피처·가중치는 롱/숏에 정확히 대칭"을 요구한다.

- 대칭 피처로 방향 비대칭을 설명할 수 있는지 검증했다: `align_4h / align_1d / drift_align / align_sum`(전부 방향 부호만 반전한 대칭 구성)의 AUC는 비섀도 풀에서 **0.383 / 0.576 / 0.481 / 0.489** — **설명하지 못한다.** (전체 풀에서는 align_sum AUC 0.372로 강한 역상관이 나오지만, 이는 TF/TC가 구조상 항상 정렬 상태라 생기는 **셋업 교락**이며 비섀도 풀에서 사라진다. 대칭 정렬 축이 방향 비대칭의 원인이라는 주장은 이 데이터로 지지되지 않는다.)
- **권고: 5-D를 깨지 않는다.** 방향 정보는 이미 승인된 채널인 `fire_rights_by_dir`(사후 거버넌스)에 계속 둔다. 실제로 그 채널은 지금 작동 중이다 — `BO short`를 강등해 놓았다(§2-F). 예측 모델(prior·δ_eff)은 대칭을 유지한다.
- 재검토 조건: `fire_rights_by_dir` 강등/복권 지연이 실측으로 20결판을 넘어가면(= 거버넌스가 너무 느려 손실이 누적되면) 그때 5-D 예외를 다시 논의한다.

## 6. 구현 순서

**전제**: 현 표본은 H2(최근 절반)에서 **어떤 규칙도 avgR 양수가 아니다**(개선안 1의 32건도 H2 −0.384). 따라서 **"지금 개선안 1을 켜서 빈도를 복구한다"는 선택은 검증 없는 점등(5-I 위반)** 이다. 순서는 "측정 도구 → 발행 게이트 → 그다음 발사 규칙"이어야 한다.

```
Phase 0 (즉시, 라이브 무영향)
  0-1  analysis/audit/diagnose_fp_fn.py — 스크립트는 본 작업에서 추가됨(수동 실행 가능).
       남은 일: 주간 잡 산출물에 편입.
       검증: 매주 Q1 퍼널·Q4 변별력 분해가 자동 기록된다.
  0-2  개선안 2 — 재적합 진단에 AUC / 셋업내부 AUC / embargo 홀드아웃 추가.
       ★ 이 시점에서 계수는 아직 발행 조건에 반영하지 않는다(측정만).
       검증: 현행 발행분의 auc_within_setup 이 0.49 로 기록될 것.

Phase 1 (발행 게이트 — 잘못된 모델이 라이브에 못 오게)
  1-1  개선안 2 (c)(d) 점등 — AUC 미달 시 기울기 0 발행.
       Gate-Out: 다음 주간 잡이 현행 계수를 '기각'하고 기울기 0 을 발행.
  1-2  개선안 3 — 기울기 적합 모집단을 발사 가능 후보로 한정(기본 OFF → 부트스트랩
       신뢰구간이 0 을 제외할 때만 ON).
       Gate-Out: 블록 부트스트랩(72h) 계수 CI 가 0 을 제외.

Phase 2 (빈도 — 모델이 정직해진 뒤에)
  2-1  개선안 1 을 WRF_FLOOR_MODE="ev" 로 추가(기본 OFF).
       사전등록 검증: 반기 2분할 × 방향별 edge 를 diagnose_fp_fn 으로 보고.
       Gate-In: 두 반기 모두 발사집합 edge ≥ 0.  ← 현 표본은 미충족. 보류가 정답.
  2-2  개선안 5 — 유니버스 확장(신규 심볼은 4주 섀도 후 편입).

Phase 3 (해상도 — 선택)
  3-1  개선안 4 — min-axis 페널티 스케일 정합. 셋업내부 AUC 개선이 없으면 채택 안 함.
```

**되돌리기**: 모든 단계가 환경변수 1개 토글로 원복 가능하며 Phase 간 의존은 0-2 → 1-1 뿐이다.

**Phase 2-1 을 지금 켜지 않는 이유**를 명시해 둔다: 빈도 붕괴는 눈에 보이는 고통이고 개선안 1은 그것을 즉시 완화한다. 하지만 H2 표본에서 그 32건의 avgR은 −0.384다. 지금 켜면 "봇이 다시 쏘기 시작했고 계속 진다"가 된다. **빈도는 문제의 증상이지 원인이 아니다** — 원인은 후보 모집단의 무조건부 엣지가 −0.11이라는 사실이며, 그것은 L2(디텍터) 층의 문제다.

## 7. 이 진단이 답하지 못한 것

1. **L2 디텍터 자체의 엣지.** 후보 집합은 수집 당시 디텍터 산물이라 재실행 불가(원본 `measures`/`ohlcv` 미보존). 전체 풀 edge −0.11이 "디텍터가 나쁘다"인지 "이 6주 시장이 나빴다"인지 구분할 수 없다. → `bars`(60봉)가 JSONL에 있으므로 **디텍터 재현 하니스**를 만들면 분리 가능하다. 다음 우선순위 후보.
2. **H1 → H2 성능 붕괴의 원인.** 기저 승률 0.287 → 0.159. 레짐 이동인지 디텍터 열화인지 미판정. UPLEG 표본은 여전히 0이다.
3. **거래비용.** 로그 미반영. avgR +0.09 수준의 결론(Fork A2)은 비용 반영 시 부호가 바뀔 수 있다.
4. **`BO short`의 진짜 부호.** edge +0.060인데 sumR −3.75. RR 분산 때문이며 24건으로는 판정 불가. `fire_rights_by_dir` 강등 유지가 안전한 선택.
5. **통계적 유의성.** 어떤 셀도 유의하지 않다. 특히 현행 발사집합 7건과 `RV short` 25건은 신뢰구간이 손익분기를 양쪽으로 넘는다.

| **3. 재적합 기울기 모집단 한정** (`WRF_REFIT_SLOPE_LIVE_ONLY`) | ⏸ 구현됨, 기본 OFF | Gate-Out(블록 부트스트랩 CI가 0 제외) 미충족 — 아직 미실행. 토글 자체는 동작 확인(비섀도 서브셋으로 기울기 재적합 후 AUC 게이트에 그대로 흡수됨 — 현재 표본에서는 어차피 게이트 미달이라 결과 동일). |
| **4. min-axis 페널티 스케일 정합** (`WRF_MIN_AXIS_SCALED`) | ⏸ 구현됨, 기본 OFF | 셋업내부 AUC 개선 측정 전. 기울기가 이미 0으로 발행되는 현재 상태에서는 `λ_eff = ratio × 0 = 0`이 되어 min-axis 페널티 자체가 무력화되는 부작용이 있다 — **기울기가 승격되기 전까지는 켜지 않는다.** |
| **5. 유니버스 확장** | ⛔ 보류 | 사용자 지시(유니버스 유지). |

**개선안2가 유일하게 기본 반영된 이유**: 나머지 세 안은 "아직 검증되지 않은 새로운
행동을 도입"하는 반면, 개선안2는 "이미 라이브에 영향을 주고 있던 재적합 파이프라인의
검증 기준 자체가 고장나 있었다"는 사실을 고치는 것이다. 대조군(config 폴백)이 이미
있고, 실패 시 결과는 더 단순하고 정직한 모델(순수 셋업 base-rate)로 수렴하므로
5-I의 "검증 없이 켜지 않는다"가 아니라 "검증 장치 자체를 고친다"에 해당한다.
