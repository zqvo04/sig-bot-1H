# C축 V5 설계 — 후보 메커니즘 비교 (2026-07-04, 구현 전 설계 문서)

> 상태: **설계/비교 단계 — 구현 착수 전 사용자 방향 확인 대기.**
> 이 문서는 코드 재검증 + 저장 스냅샷 예비 실측(§3)을 근거로 후보 메커니즘을
> 비교한다. 모든 수치는 단일레짐(DOWNLEG/CHOP, UPLEG 0건) 표본의 탐색적 조회이며
> **채택 판정이 아니다** — 최종 판정은 §6의 사전등록 게이트로만 한다.

## 0. 요약 (TL;DR)

반전 국면을 4단계로 나누면 현행 C축의 공백이 정확히 보인다(§2). V4/P0 킬은
1단계(낙하)와 3단계(리클레임 후 지각 페이드)를 막는 데 성공했지만, **2단계(바닥
형성)에서 반전 C를 열어주는 정보가 없고, 3단계(새 레그 확립)에서 추종 C를
끌어올리는 메커니즘이 없어 어느 셋업도 못 쏘는 사각지대**가 남는다.

예비 실측(§3)의 핵심: 리클레임 증거는 **상태(state)로는 엣지 0, 신선 플립
이벤트 단독으로는 휩소(역엣지), "선행 반대레그 이후의 신선 플립"으로만 양방향
대칭 개선**(+24h 롱 60.7%/숏 68.8%, 단 n=44)을 보인다. 즉 "언제 봐도 참인 구조
정렬"이 아니라 "레그가 죽고 막 뒤집힌 직후"라는 **이벤트 조건부**로만 정보가 있다.

후보 5안 중 권고 조합(§7):
1. **V5-0(공유 증거 커널 리팩터, 동작불변)** + **계측 필드 선행 추가** — 즉시.
2. **V5-B(리클레임 부스트 = P0 킬의 쌍대)** — 기본 OFF·섀도 A/B로 구현. 3단계
   사각지대를 직접 겨냥하며, 기록된 미발사 후보의 재생만으로 오프라인 검증 가능.
3. **V5-R(반전 C에 1H 선행구조만 주입, v2-lite)** — 코드보다 하니스 먼저:
   v1/v2/v5-lite 3-way IC 비교로 방향만 확인, 채택은 v2와 동일한 UPLEG 게이트.

## 2. 문제의 재정식화 — 반전 국면 4단계와 공백 지도

하락→상승 전환을 예로 들면(상승→하락은 완전 대칭):

```
Phase 1  낙하 임펄스     : 페이드 대상 레그 살아있음 + 극단 스트레치
Phase 2  소진·바닥 형성  : 스윕(failed_break)·CHoCH·반전캔들·다이버전스 발생
Phase 3  리클레임        : VWAP/EMA 재탈환 + 구조플립 (reclaim_n ≥ 2)
Phase 4  추세 성숙       : 4H/1D 구조 플립 → 수일 후 btc_macro 태그 도착
```

| 단계 | 쏴야 하는 셋업 | 현행 C축의 동작 | 판정 |
|---|---|---|---|
| 1 | 없음(칼받기 금지) | `_impulse_kill`이 롱 페이드 차단 | ✅ v4 검증됨 |
| 2 | **RV/MR 롱** | v1 C = 0.25 + 0.75·(−1) = **−0.5 → 차단(FN)**. 유일한 선행정보(1H 스윕/CHoCH)가 반전 C에 미주입 | ❌ **공백 A** |
| 3 | **TF/BO 롱** | P0가 반전 진입을 "지각"으로 킬(✅ 정당). 그러나 추종 C는 slow 구조(−0.8 상당)에 눌려 P1 fast(+0.20 가중)로도 C≈−0.6 → min-axis 페널티로 전멸 | ❌ **공백 B** |
| 4 | TF | macro 태그 도착 후 정상 발화 | ✅ (단 수일 지각) |

**핵심 관찰 — 킬의 쌍대성 단절**: P0 킬이 Phase 3에서 "반전 진입은 이제
늦었다"고 판정하는 바로 그 증거(`_reclaim_n ≥ 2`)는, 논리적으로 "추종 진입은
이제 이르지만 유효하다"는 증거이기도 하다. 현행 코드는 전자(킬)만 소비하고
후자(부스트)를 버린다. 공백 B는 새 신호가 필요한 게 아니라 **이미 계산된 증거의
반쪽이 버려지는 문제**다.

수치로: Phase 3에서 slow=−0.80, fast=+1.0이면 추종 롱 C = −0.60. L=0.7, F=0.3
이어도 z = −0.15 −0.66 +0.91 +0.36 = +0.46에서 min-axis 페널티 2.5·(0.10−(−0.6))
= 1.75가 빠져 P̂ = 0.22 — floor 0.58에 한참 못 미친다. C가 +0.25만 되어도
P̂ = 0.65(cap) ≥ floor로 발사권이 생긴다. 즉 이 사각지대는 C축만으로 갈리는
구간이 맞다(라우팅 제약은 §5-B 한계 참조).

### 3-3. 함의

1. 어떤 후보든 **상태가 아니라 이벤트(신선한 전환) + 맥락(선행 반대레그)**으로

3. 엣지 반감기 ~24h → 부스트가 열어주는 발사는 t_max 짧은 쪽이 정합적이며,
   C 클램프 수위를 +1.0이 아니라 중간(+0.25~+0.5)으로 묶을 근거이기도 하다.

## 4. 설계 원칙 (실패 계보에서 도출)

1. **예측 금지, 사후 인식만**: "다음 봉이 추세 시작인가"를 재는 연속 상태피처는
   3회 사망(V3, tune_regime, §3-1 상태행). 완결된 구조 사건(스윕-후-복귀,
   다중확증 리클레임)에만 반응한다.
2. **클램프, 합산 금지(5-J)**: v4/P0의 성공 패턴은 `min(C, x)` 엔벨로프 클램프.
   V5의 양(+)의 메커니즘도 `max(C, x)` 클램프로 — 가산 보너스 금지.
3. **증거 계산은 1회, 소비는 양방향**: 킬과 부스트가 같은 프리미티브를 공유해야
   P1-미전파류 버그가 재발하지 않는다(공유 커널).
4. **가중치 튜닝 금지**: 기존 검증 계수(P1의 0.20, base 0.25, envelope [−0.5,1])
   재사용. 새 자유도는 토글과 고정 맵으로 제한.
5. **검증은 방향분리 + BTC초과수익 + 라벨-프리 지표 병행**: §3-2의 아티팩트가
   기본 검증을 통과해버리는 것을 구조적으로 차단.

### V5-0 — 공유 증거 커널 (리팩터, 동작 불변)

**문제**: `_ctx_align`/`_ctx_exhaustion`/`_impulse_kill`/`_reclaim_kill`이 같은
raw 필드를 제각기 읽는다. P1이 반전형에 전파 안 된 것은 우연이 아니라 이 구조의
필연이다.

**설계**: 방향-부호 연속 증거를 한 함수로 모은다.

```python
def _struct_evidence(ctx, raw, pcts) -> dict:
    """모든 C축 소비자가 공유하는 방향-부호 증거 묶음(+1=강세)."""
    return {
        "slow":       _ctx_struct_align_slow(ctx, raw),   # 거시·바이어스·4H·1D (기존 가중 그대로)
        "fast":       _fast_struct(raw),                  # 1H 스윕/구조/EMA/VWAP (기존 그대로)
        "reclaim_up": _reclaim_n(raw, "long"),            # 0~3
        "reclaim_dn": _reclaim_n(raw, "short"),
        "alive_up":   _leg_alive_n(raw, "short"),         # 상방레그 생존(숏 페이드 관점)
        "alive_dn":   _leg_alive_n(raw, "long"),
        "stretch":    pct.to_axis(pcts.get("loc_vwap")),  # 부호 스트레치
    }
```

`_ctx_align`/`_ctx_exhaustion`은 이 dict에서 조합만 하고, 킬/부스트는 이 위의
엔벨로프 연산자가 된다. **토글 불요(순수 리팩터)** — 수용 기준: 저장 후보 전량
재계산 시 C 비트 동일(회귀 스크립트로 확인).

**수정 지점**: detectors.py 49-195 재배치. 외부 인터페이스 불변.

### V5-R — 반전 C에 1H 선행구조만 주입 (v2-lite)

**설계**: v1의 fade_align에 fast_struct를 소폭 블렌드. v2가 주입하는 4H/1D
구조(후행 — Phase 2에선 아직 반대 방향)는 넣지 않고, **선행 정보(1H 스윕·CHoCH·
VWAP)만** 넣는다.

```
C_rev(dir) = clip(base + (1−base)·[(1−fr)·fade_m(dir) + fr·fade_fast(dir)])
  fade_m    = ±m            (v1 그대로, 부호=진입방향)
  fade_fast = ±_fast_struct (P1과 동일 프리미티브)
  base = 0.25 (기존), fr = WRF_REV_FAST_W = 0.20 (P1 계수 재사용 — 신규 튜닝 없음)
```

envelope [−0.5, 1.0]·극단 의미론 보존(macro 유효가중 0.75→0.60 — v2의 0.34보다
훨씬 보수적). Phase 2 바닥에서 macro=−1·fast=+1이면 C = −0.5 → **−0.2**: 하드차단이
풀리고 min-axis 연속 페널티 구간으로 이동(L/F가 아주 강할 때만 통과) — "조금
열되 floor에 위임"이라는 기존 철학과 정합.

**과적합 자기반박**: 이 표본에서 좋아 보인다면 그 이유는 v2와 동일하게 "심볼이
1H에서 반대로 움직일 때 페이드를 감점"하는 방향노출 때문일 수 있고, 그 감점이
옳은지는 단일레짐에서 판가름 불가(v2가 정확히 이걸로 대기 중). **따라서 채택
게이트는 v2와 동일(UPLEG 다레짐)로 묶는다.** 지금 할 일은 코드가 아니라
하니스(§6)에서 v1/v2/v5-lite 3-way IC·방향분리 비교뿐.

**수정 지점**: `_ctx_exhaustion`(detectors.py:171-195) 분기 1개.
**토글**: `WRF_REV_CTX_V5_FAST`(기본 OFF), `WRF_REV_FAST_W`(기본 0.20).

### V5-B — 리클레임 부스트 (P0 킬의 쌍대) ★핵심 제안

**설계**: P0가 소비하고 버리는 증거의 반쪽을 추종형 C의 **max-클램프**로 재활용.

```
추종형(TF/BO), 방향 dir에 대해:
  boost_armed = (reclaim_n(raw, dir) ≥ 2)                       # P0와 동일 프리미티브·동일 임계(재사용)
              ∧ (신선: dist_vwap 부호플립 ≤ K봉 전 ∨ dist_ema20 부호플립 ≤ K봉 전)
              ∧ (선행 반대레그: slow(dir) < 0)                   # 느린 강이 아직 반대 = 레그가 실재했고 지각 중

  C' = max(C_align, CMAP[reclaim_n])     # CMAP = {2: +0.25, 3: +0.50} 고정(튜닝 대상 아님)
```

- **왜 이번엔 다른가** (게이트 열기 실패 계보에 대한 답):
  1. stretch/decel류는 Phase 1~2 극단에서 **바닥을 예측**하려 했고 죽었다.
     V5-B는 Phase 3에서 **이미 완결된 다중확증 리클레임**에 반응한다 — 진입
     지점이 다르고(바닥이 아니라 첫 되돌림/재가속), 예측이 아니라 인식이다.
  2. 같은 프리미티브의 킬 방향은 실측 지지가 있다(P0가 손실 발사만 순제거).
     킬이 통한다 ≠ 부스트가 통한다이지만, **새 신호 발명이 아니라 검증된 신호의
     대칭 완성**이라 자유도 추가가 최소다.
  3. §3-1: 이벤트+선행레그 조건이 유일하게 양방향 대칭 양성.
- **왜 여전히 위험한가** (자기반박): max-클램프는 신규 발사를 만든다 — v4/P0가
  "닫기 전용이라 출혈 없음"으로 통과한 안전 논리가 **적용되지 않는다**. §3-1의
  60.7%/68.8%는 n=44·다중조회·단일레짐이다. 휩소 리클레임(플립 후 재역전)이 이
  표본보다 흔한 레짐(급변동 chop)에서는 손실 개방이 될 수 있다. → **기본 OFF,
  섀도 밴드 관찰 → 오프라인 재생 게이트 통과 후에만 점등.**
- 정합성 체크: TF 진입엔 여전히 precond(눌림+모멘텀/구조)와 L/F, floor가 필요
  하다. 부스트는 "C가 지각 거시에 눌려 죽는 것"만 풀지, 명백히 나쁜 진입을
  살리지 않는다(§2 수치 예: C −0.6→+0.25일 때만 P̂ 0.22→0.65).
- **한계(정직)**: Phase 3에서 regime_1h가 RANGING이면 TF는 allowed_setups에
  없을 수 있다(라우팅은 V5 범위 밖 — grind 연구에서 회수 상한 ~15% 구조적 확인).
  부스트의 실효 도달 범위는 BO(RANGING 허용) + 4H 플립 후 TF 앞당김으로 제한될
  수 있다 — 하니스가 "부스트로 열린 발사 수"를 직접 세서 실효를 판정한다.
- **BR 비적용**: BR은 무장 자체가 약해 C 개선으로 구제 안 됨이 반증 완료.
  V5-B는 추종형 전용이라 BR 무관(BR C에 손대지 않음).

**반전형에도 부스트?** — 반전형에 같은 부스트를 걸면 P0 킬과 정면 모순된다
(같은 증거로 반전 C를 올리고 내림). P0의 판정("리클레임 후 반전 진입은 지각")을
존중해 **반전형은 V5-R로만, 부스트는 추종형으로만** — 역할 분리가 쌍대성의 올바른
구현이다.

**수정 지점**: `_ctx_align`(detectors.py:84-87)에 클램프 1개 + features.py에
신선도 필드 2개(아래 계측). **토글**: `WRF_CTX_RECLAIM_BOOST`(기본 OFF),
`WRF_RECLAIM_FRESH_K`(기본 6봉). CMAP·임계 2는 P0 재사용·고정.

**계측 선행(즉시, 무위험)**: features.py가 이미 만드는 `dist_vwap`/`dist_ema20`
시계열에서 `bars_since_vwap_flip`/`bars_since_ema20_flip`(마지막 부호전환까지 봉
수, 무상태)을 raw에 **기록만** 추가. 지금 넣어야 몇 주 뒤 V5-B 검증 표본에
신선도가 박제된다(bars 저장이 72행뿐이라 소급 재구성이 빈약한 문제의 해결책).

### V5-F — 오더플로우 종결 확증 (F→C 교차)

**설계 스케치**: 진입방향 반대 레그의 "종결 이벤트"(사이디드 청산 플러시
`liq_signal`, OI `reversal_*` 사분면)를 리클레임 확증 카운트에 +1로만 반영
(블렌드 가중 아님 — 이산 확증). 킬은 더 일찍, 부스트는 더 확실하게.

**보류 사유**: ① C가 F의 정보를 재소비하면 로지스틱 prior에서 flow 유효가중이
이중계상된다(직교성 훼손 — wC·wF 재추정 없이는 위험). ② liq/OI 이벤트는 희소해
지금 표본으론 조건부 실측이 불가능. ③ V5-B가 자리잡은 뒤 확증 소스 확장으로
붙이는 게 자유도 관리상 옳다. → 설계만 남기고 **B 이후 재검토**.

### V5-D — 신선도 가중 블렌드 (기각 권고)

"가장 최근에 플립한 타임프레임에 가중"하는 안은 §3-1에서 **신선 플립 단독 =
역엣지(휩소)**로 실측 기각됐다. 신선도는 가중이 아니라 **조건**(V5-B의
boost_armed)으로만 쓴다. 연속 "C 속도" 피처도 같은 이유 + decel 전례(v3 33.3%)
+ bars 표본 기근으로 기각. 재론 조건: bars 축적 ≥1,000행 + 이벤트 조건부로
재정식화된 새 가설.

## 6. 검증 하니스 설계 — `analysis/audit/verify_caxis_v5.py` (사전등록)

기존 verify_p012/verify_br_caxis 패턴(저장 후보 재생, C만 교체, tb 라벨 재사용,
72h embargo, 시간분할) 위에 다음을 **필수 추가**한다:

1. **방향분리 보고**: 모든 지표를 롱/숏 분리 + 합산 병기. 수용 기준은 "각 방향
   비열등 ∧ 합산 개선"(합산만 보면 §3-2 베타 아티팩트가 통과한다).
2. **BTC초과수익 채점 병행**: `labels.exret` 재사용 — 알트 결판을 raw R과
   BTC초과 R 양쪽으로. 단일레짐 베타 1차 상쇄.
3. **라벨-프리 프리미티브 게이트**: 부스트/킬 조건의 이벤트 지속성(§3-1 방식)을
   승률과 독립으로 상시 추적 — 메커니즘 신뢰도와 수익성을 분리 계측.
4. **개방형 메커니즘(V5-B) 전용 게이트**: "부스트로 새로 열린 발사"만 모아
   실현 win% ≥ floor ∧ exp_R > 0 ∧ 방향별 비열등. 열린 발사가 0이면 무의미
   판정(라우팅 상한 확인).
5. **UPLEG 최소표본 사전 명시** (fade-방향 판정 공통 게이트, v2와 동일 적용):
   UPLEG 태그 스냅샷 ≥ 300 ∧ UPLEG 구간 반전 결판 ≥ 20. 미달이면 "판정 불가
   유지"를 결과로 기록(기준 완화 금지).
6. **다중조회 규율**: 이 문서 §3의 탐색 조회를 명시적으로 "가설 생성"으로
   격리하고, 하니스의 판정 기준·지표·컷을 코드에 박은 뒤에는 변경 금지(위반 시
   결과 무효 — verify_br_caxis의 사전등록 관행 승계).

검증 가능성 확인: V5-B/R 모두 **기존에 기록된 후보의 C만 바꾸는** 변경이라
신규 발사도 "기록됐으나 미발사였던 후보"에서 나온다 → 저장 tp/sl/path로
triple_barrier 재생 가능(신규 후보 생성이 없어 반사실 완전 재현).
