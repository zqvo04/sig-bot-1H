## 1. 현재 알고리즘 구조

### 1-A. 파이프라인 실측 흐름

```
main.py (심볼 루프, 1H 봉마다)
 └─ engine.run_engine(symbol, measures, ohlcv, collected, btc_macro)
     ├─ L1  features.build_features()
     │      raw(=schema v3 원시피처) / pct(자기분포 백분위 200봉) /
     │      ctx{regime_1h, regime_4h, bias_1d, btc_macro, allowed_setups}
     │      · allowed_setups = REGIME_SETUPS[regime_1h] (+RANGING→BO 추가,
     │        +regime_4h TRENDING→TF, +regime_4h SQUEEZE→BO, +TC)
     │
     ├─ Regime Routing (_regime_routing_state)
     │      4H EMA ∧ 1D bias ∧ (1D EMA구조 ∨ btc_macro) 3중 정렬 → 'up'/'down'
     │      → TF 강제 허용 + 역방향 MR/RV/BR 후보 제거. 미정렬이면 무작동.
     │
     ├─ L2  detectors.detect_all() — 6디텍터 × 양방향
     │      TF 눌림추종 / TC 채널라이드(섀도) / BO 돌파-리테스트 /
     │      MR 밴드극단 / RV 추세소진 / BR 밴드복귀(섀도)
     │      각 후보 = precond(하드게이트) + 직교 3축 C/L/F ∈ [-1,1]
     │
     ├─ L4보조 levels.compute_levels()
     │      entry = 현재가(다음 봉 시가 근사)
     │      BO : TP=박스높이, SL=돌파경계∓ATR쿠션(WRF_BO_SL_NEAR)
     │      MR : TP=박스중심, SL=경계외곽∓ATR
     │      TF/RV: SL=직전 10봉 스윙∓1.5·ATR (1.2%~5% 클램프),
     │             TP = SL거리 × 고정 RR (TF 2.5 / RV·BR 2.0)   ← 구조 TP 아님
     │      TF: WRF_TF_TRAIL로 trail_dist=3·ATR 주석 + t_max 48→72
     │
     ├─ L3  calibration.evaluate()
     │      p_prior = min(0.65, σ(b0[setup] + 1.1·C + 1.3·L + 1.2·F − λ·min-axis페널티))
     │      p_cal   = σ(prior_logodds + δ_eff[cell]) , cell=(setup|regime_1h|btc_macro)
     │      WRF_CALIB_DISABLED=true(기본) → **발사에는 p_prior만 사용**
     │      fire_rights = 셀의 사후검정 결과('live'|'shadow')
     │
     ├─ L0  veto.evaluate()
     │      ① 스프레드>8bp ② 진입정면 청산캐스케이드 ③ 데이터 신선도>90분
     │      ④ MACRO_HEADON: 롱∧DOWNLEG / 숏∧UPLEG (RV·BR은 면제)
     │
     └─ L4  발사판정
            EV 게이트: EV = P̂·RR − (1−P̂) ≥ 0.15 ∧ RR ≥ 0.85
            격리: setup ∈ WRF_SHADOW_SETUPS(=BR,TC) 또는 fire_rights=='shadow'
            fire = P̂ ≥ floor(0.58) ∧ ¬VETO ∧ EV통과 ∧ ¬격리
            size = 1.0 + 1.0·(P̂−floor)/(1−floor)
            (setup,dir) 중복 제거(BR은 RV 패밀리로 합침) → P̂ 내림차순
```

### 1-B. Exit(청산) 로직 — `notion_wrf._eval_signal`

봉 단위로 t_max까지 전진하며:
- MFE/MAE = (유리/불리 극값 − entry) / R_dist, **매 봉 SL 판정 전에 갱신** → SL 히트 봉의 MAE는 1.0을 넘을 수 있다(윅 오버슛).
- 동일 봉 SL·TP 동시 터치 → **SL 우선**(보수적).
- t_max 도달 → 종가 시장가 청산, `EXPIRED_WIN`/`EXPIRED_LOSS`, Status는 `SCRATCH`(승률 모집단에서 제외).
- **중간 청산·부분익절·본전스톱·MFE 기반 관리는 없다.** TF의 trail_dist는 라이브에 주석으로만 실리고, 원장 채점(`_eval_signal`)은 이를 소비하지 않는다 — 오프라인 `labels._trailing_barrier`만 소비.

## 3. Root Cause Analysis — 최근 성능 악화

### 3-A. 무엇이 변했나 (블록별 분포 이동)

| 블록(발화순) | n | sumR | avgR | 결판승률 | SL% | MFE | MAE | 평균 P̂ |
|---|---|---|---|---|---|---|---|---|
| 1–20 (6/19~6/29) | 20 | +9.39 | +0.470 | 50.0% | 25% | 1.43 | 0.70 | 0.643 |
| 21–40 (6/30~7/17) | 20 | +1.94 | +0.097 | 35.3% | 55% | 1.23 | 0.82 | 0.633 |
| 41–59 (7/17~7/29) | 19 | **−7.25** | −0.381 | **12.5%** | **74%** | 0.96 | 0.93 | 0.627 |

**P̂은 거의 변하지 않았는데(0.643→0.627) 실현 승률은 50%→12.5%로 무너졌다.** 즉 악화는 P̂이 감지하지 못한 축에서 발생했다.

변수 분포 이동:

| 변수 | 블록1 | 블록2 | 블록3 |
|---|---|---|---|
| Setup: BO / BR / RV / TF | 0 / 65% / 30% / 0 | 50% / 30% / 5% / 15% | **58%** / **0%** / 21% / 21% |
| BTC Macro: CHOP | 35% | 90% | **100%** |
| Regime 4H: RANGING | 60% | 60% | **84%** |
| Direction: SHORT | 65% | 55% | 53% |

### 3-B. 인과 사슬

1. **BR 셧다운으로 셋업 구성이 강제 이동했다.** BR(밴드반전)이 `WRF_SHADOW_SETUPS`로 섀도 강등되면서 블록3의 BR 발화가 0이 됐다. 그 빈 자리를 **BO가 채웠다**(0%→58%). BR 제거 자체는 옳았다(BR 19건 −2.12R, 오프라인 pooled WR 0.214). 문제는 대체재가 검증 없이 들어왔다는 점이다.

2. **BO는 RANGING에서 발화하도록 열려 있다**(`WRF_BO_IN_RANGING=true`, `features.allowed_setups`). 4H가 RANGING으로 이동한 구간에서 BO가 전체의 58%를 차지했다. 4H 레인지 안의 1H 돌파는 정의상 페이크아웃 모집단이다.
   - BO SHORT × RANGING: **12건, avgR −0.57, SL 히트 75%**
   - BO LONG × RANGING: 7건, avgR **+1.41**, SL 히트 14%

3. **btc_macro가 거시 베토를 무력화했다.** `MACRO_HEADON` 베토(veto ④)는 `btc_macro ∈ {UPLEG, DOWNLEG}`일 때만 작동한다. BTC 7D 변화 ±3% 임계(`WRF_MACRO_UP_PCT`)에 걸려 블록3은 **100% CHOP** → 역행 진입에 대한 하드 브레이크가 전 구간 무작동. 실제로는 같은 기간 **ETH가 +9.7%, BTC +1.5%** 드리프트 중이었고, ETH SHORT는 **11건 −8.70R, SL 82%**로 단일 최악 코호트다.

4. **RV의 soft-precond가 저품질 롱을 통과시켰다.** `WRF_RV_SOFT_PRECOND=true`가 CHoCH·리테스트 필수를 L 감쇠로 대체했다. 그 결과 블록3의 RV 롱 4건 중 3건이 구조확증 없는 "소진우위"였고 **전부 −1R**(0/3). 반면 확인 3개 이상 RV 9건은 avgR +0.87, 승률 78%.

**한 문장 요약**: 최근 악화의 핵심 원인은 *심볼·방향*이 아니라 **"검증되지 않은 셋업(BO SHORT)이 검증 탈락한 셋업(BR)의 빈도를 물려받았고, 그 사이 유일한 방향 브레이크(btc_macro 베토)가 CHOP 태그로 꺼져 있었다"** 는 거버넌스 공백이다.

**TF는 특정 레짐 문제가 아니라 구조적 문제다.** 근거 3가지:
1. 라이브 7건 중 6패, 유일한 승리는 TP가 아니라 만기청산 익절(`EXPIRED_WIN`, HYPE 숏).
2. 레짐이 갈리지 않는다 — 오프라인 셀 `TF|RANGING|CHOP` 0/6, `TF|SQUEEZE|CHOP` 0/3, `TF|TRENDING|CHOP` 0/2. **TRENDING에서도 0승.**
3. 기하가 자기모순이다. TF의 SL은 "직전 10봉 스윙 ∓ 1.5·ATR"인데 이는 **눌림의 바닥을 그대로 스톱으로 삼는 것**이고, TP는 그 거리의 2.5배(진입가의 6.4~8.7%)다. 실측 MFE 평균 0.93R → TP는 사실상 도달 불가, SL은 정상 눌림 노이즈 안에 있다. TF의 라이브 SL 히트 5건 중앙 소요 16봉.

**RV는 레짐이 아니라 precond 강도의 문제다.**

| RV 확인수 | n | avgR | 승률 |
|---|---|---|---|
| confirms = 3 | 9 | +0.87 | 78% |
| confirms = 2 (soft only) | 2 | −1.00 | 0% |
| 시퀀스 "소진우위"(CHoCH·리테스트 둘 다 없음) | 3 | −1.00 | **0/3** |

**BO는 방향의 문제다** (4-A 표). 그리고 BO의 RR 인플레이션이 EV 게이트를 통과시킨다 — RR>3인 6건 중 5건이 BO, 그중 숏 4건은 **전부 SL_HIT**(MAE 1.04~2.16). `WRF_BO_SL_NEAR=true`가 SL을 박스높이→돌파경계+1ATR로 당기면서 RR을 기계적으로 부풀리는데, P̂에는 최대 0.15의 타이트니스 페널티만 반영된다.

### 4-D. C / L / F 축

| C 구간 | n | avgR | 결판승률 |
|---|---|---|---|
| ≤ 0.24 | 10 | +0.277 | 37.5% |
| 0.24~0.50 | 21 | **+0.464** | 50.0% |
| 0.50~0.65 | 10 | **−0.432** | **0.0%** |
| > 0.65 | 18 | −0.229 | 16.7% |

corr(C, R) = **−0.205**, 결판만 보면 −0.277. **C축은 부호가 뒤집혀 있다.** 다만 방향별로 쪼개면 LONG에서 −0.90(n=18), SHORT에서 +0.17(n=25)로 갈리고, LONG의 고-C 코호트는 사실상 TF 롱(C 평균 0.64)이다 — **C의 음의 IC는 상당 부분 TF 교락**이다. C 단독을 반전시키는 처방은 위험하고, TF를 먼저 격리한 뒤 C를 재측정해야 한다.

corr(L, R) = +0.075, corr(F, R) = −0.061 → **L·F는 사실상 무정보**. 즉 `prior_logodds = b0 + 1.1C + 1.3L + 1.2F`의 세 가중치 모두 현재 표본에서 근거가 없다.

| EXPIRED_WIN | 13 | 1.51 | 1.28 | 0.49 | 44.3 | 2.14 |

### 판정 ①: 손실의 주범은 **Entry**다 (Exit이 아니다)

- SL_HIT 30건의 **MFE 중앙값이 0.48R**. 절반은 0.5R도 못 가고 죽었다. MFE ≥ 1.0R을 찍고서 SL로 간 건 **7/30(23%)** 뿐이다.
- 즉 "이익을 반납한 트레이드"는 소수고, 대부분은 **진입 직후부터 틀렸다.** Exit 관리로 구제할 수 있는 모집단이 애초에 작다.
- 승자와 패자의 MAE가 극명히 갈린다: 승리 26건 중 MAE ≥ 0.8R은 **3건뿐**. 반대로 전체에서 MAE ≥ 0.8R인 33건의 R>0 비율은 **9%**. 좋은 트레이드는 거의 역행하지 않는다 → **역행이 시작되면 그건 잘못된 진입이다.**

### 판정 ②: SL은 "너무 타이트"가 아니라 **"방향이 틀린 자리에 놓였다"**

- SL_HIT 30건 중 **16건이 MAE ∈ [1.0, 1.1]** — 스톱을 간발로 스쳤다. 이것만 보면 "SL을 조금만 넓히면 살았다"로 읽고 싶어진다.
- 그러나 SL 거리(진입가 대비 %) 3분위를 보면 **넓은 SL이 더 나쁘다**:

| SL 거리 3분위 | n | 평균 SL% | SL 히트율 | avgR |
|---|---|---|---|---|
| 0.97~1.20% | 26 | 1.19% | 42% | **+0.47** |
| 1.20~2.23% | 13 | 1.63% | 54% | −0.13 |
| 2.23~4.85% | 20 | 3.02% | 60% | **−0.32** |

  SL을 넓히면 TP도 같은 배수로 멀어지기 때문에(P4) 이득이 상쇄된다. **SL 폭 자체는 1차 원인이 아니다.**
- 결론: SL 조정은 우선순위가 낮다. CSV만으로는 "SL을 넓혔으면 회복했는가"를 알 수 없다(경로가 SL에서 잘림) — **JSONL path 재생으로만 검증 가능**.

### 판정 ③: TP와 Time-Exit은 **2차적이지만 실재하는** 손실원

- 만기청산 16건: MFE 평균 1.51R, **13/16이 1.0R 이상 갔는데 실현은 평균 +0.51R**. 2.0R 이상 간 건 2건뿐인데 TP는 2.0~2.5R에 있다.
- 보수적 반사실(SL 히트는 −1R 고정, 비-SL 트레이드만 MFE≥X일 때 X에서 청산):

| 가상 TP | sumR | (기준 +4.08R) |
|---|---|---|
| 1.0R | −2.42 | 악화 |
| 1.2R | +2.28 | 악화 |
| **1.5R** | **+5.30** | **+1.22R 개선** |
| 1.75R | +4.54 | +0.46R |

  개선폭은 **59건에 +1.2R**로 제한적이다. **TP 축소만으로는 문제가 풀리지 않는다.** 다만 TF처럼 TP가 MFE 분포 밖에 있는 케이스는 별개로 교정 대상이다.

### 최종 진단

```
손실 기여도(추정)   Entry 선택 ≫ TP/Exit 구조 > SL 배치
```
- **Entry**: 잘못된 셋업×방향 조합의 발사 자체 — BO SHORT(−7.81R), TF(−3.81R), BR(−2.12R), RV soft(−3R). 단순 제거 반사실: BR+BO SHORT+TF 제외 시 20건 **+17.83R (avgR +0.89)**.
- **Exit**: TP 도달 불가 구조 + MFE 반납 → 약 **+1~2R** 회수 여지.
- **SL**: 근거 불충분. 별도 검증 후 판단.

### 개선안 1 — Directional Drift Gate: `btc_macro` 의존 방향 베토를 심볼 자기 드리프트 백분위로 교체

| 항목 | 내용 |
|---|---|
| **1. 개선 대상** | `src/wrf/veto.py::directional_vetoes` (MACRO_HEADON), `src/wrf/btc_macro.py`, `src/wrf/features.py`(신규 백분위 피처) |
| **2. 현재 문제** | 역행 진입에 대한 유일한 하드 브레이크가 `btc_macro`(BTC 7D 변화 ±3% 절대 임계)에 묶여 있다. 이 태그가 CHOP이면 베토가 완전히 꺼진다. 게다가 BTC 태그를 알트에 그대로 적용해 심볼 자신의 드리프트를 무시한다. RV·BR은 아예 면제(`WRF_RV_MACRO_EXEMPT`)라 반전 셋업엔 브레이크가 없다. |
| **3. 데이터상 근거** | ① 59건 중 44건(75%)이 `btc_macro=CHOP` — 베토가 대부분 무작동. 블록3은 100% CHOP. ② 같은 기간 실제 드리프트는 ETH +9.7% / BTC +1.5% / HYPE −18.2%. ③ ETH SHORT 11건 **−8.70R, SL 82%, MFE 0.67** — 상승 드리프트 심볼의 숏이 단일 최악 코호트. ④ 4H Regime × Direction: 4H RANGING에서 SHORT −0.56 / LONG +0.74, 4H TRENDING에서는 SHORT +0.21로 정상화 → 방향 실패는 "상위 프레임 대비 역행"과 결부돼 있다. |
| **4. 제안하는 변경 방향** | `btc_macro`를 **유지하되 대체하지 않고**, 심볼 자기 드리프트 백분위 축을 새로 만들어 방향 베토의 트리거로 삼는다 (CLAUDE.md 5-C 준수: 절대 임계 금지, 자기분포 백분위). 5-D 대칭 유지: 롱/숏에 부호만 반전해 동일 적용. |
| **5. 변경해야 할 알고리즘 로직** | **(a) L1 신규 측정** `features.build_features`에 `drift_norm = (close − close[−N]) / ATR` (N = 4H 기준 ≈ 42봉)을 계산하고, `pct.pct_rank`로 200봉 자기분포 백분위 `pct["drift"]`를 산출. 순수 측정이므로 L1 책임 범위 내(5-G).<br>**(b) L0 베토 확장** `directional_vetoes`의 ④를 다음으로 교체:<br>`DRIFT_HEADON = (long ∧ pct.drift ≤ WRF_DRIFT_LO) ∨ (short ∧ pct.drift ≥ WRF_DRIFT_HI)`<br>기존 `MACRO_HEADON`은 그대로 두고 **OR**로 결합(되돌리기 가능, 기본값이 기존 동작 보존하도록 `WRF_DRIFT_VETO=false`로 출시).<br>**(c) 면제 정책 재조정** RV/BR 면제(`WRF_RV_MACRO_EXEMPT`)는 `MACRO_HEADON`에만 유지하고 **DRIFT_HEADON에는 적용하지 않는다** — 반전 셋업이야말로 드리프트 역행 위험의 본진이기 때문. 단 반전 셋업은 극단 백분위(예: ≥0.95)만 차단하도록 임계를 분리. |
| **6. 기대 효과** | ETH SHORT 코호트(−8.70R) 중 상승 드리프트 상위 백분위 구간의 진입을 차단. 방향 알고리즘을 분리하지 않고도 P1의 손실 대부분을 제거. `btc_macro=CHOP` 구간의 브레이크 공백 해소. |
| **7. 부작용 / 위험** | ① 추세 초입에서 정당한 카운터트렌드(RV/MR)까지 차단해 반전 엣지가 소멸할 수 있다 — 목적함수(max N s.t. WR≥floor)의 N을 깎는다. ② 드리프트 백분위는 후행 지표라 급반전 시 잘못된 쪽을 막는다. ③ HYPE 숏(하락 드리프트)은 이 게이트를 통과하는데 실제로는 −3.30R이었다 → 이 게이트가 SHORT 손실 전부를 설명하진 않는다. |
| **8. 과적합 가능성** | **중간**. 임계(LO/HI)가 튜닝 노브가 되는 순간 59건에 과적합된다. 완화: 임계를 0.10/0.90처럼 **기존 극단컷 상수와 동일한 값으로 고정**하고 단독 튜닝 금지. 드리프트 윈도 N도 4H=42봉으로 고정(레짐 정의와 정합). 실질 자유도 0을 목표로 한다. |
| **9. 검증 방법** | JSONL v3 후보 전량(258결판)에 대해 `analysis/audit/` 사전등록 스크립트 작성 → ① 게이트 적용 전후 **발사집합 승률·평균R·발사수**를 방향별로 분리 보고, ② 시간 2분할(6월 / 7월) 모두에서 부호 일관성 확인, ③ **BTC초과수익(exret) 기준**으로도 개선이 유지되는지 확인(베타 착시 차단), ④ HYPE 숏처럼 게이트를 통과하는 손실 코호트를 별도 집계해 게이트가 "설명하지 못하는 손실"의 크기를 명시. Gate-In: 발사수 감소분당 승률 개선이 두 시간구간 모두에서 양수. |

### 개선안 2 — P̂ 재보정: prior 재적합 + 보정 경로 점등 (P̂ 해상도 복원)

| 항목 | 내용 |
|---|---|
| **1. 개선 대상** | `src/config.py` (`WRF_PRIOR_B0/WC/WL/WF/CAP`, `WRF_CALIB_DISABLED`), `src/wrf/calibration.py`, `analysis/calibrate.py` |
| **2. 현재 문제** | prior가 체계적으로 2배 낙관적이고, cap 0.65 + floor 0.58 사이 0.066 폭에 전 신호가 눌려 **P̂이 순위정보를 잃었다**. 동시에 그 문제를 정확히 학습한 δ_eff가 `WRF_CALIB_DISABLED=true`로 라이브에 도달하지 않는다. 사이징도 `size ∝ (P̂−floor)`이므로 해상도 상실이 사이징 왜곡으로 전이된다. |
| **3. 데이터상 근거** | ① P̂ 전량 `prior`, 32/59가 cap 0.650에 정확히 고정. ② corr(P̂, R) = **−0.148** (결판 −0.143). ③ P̂ 최상위 구간(0.645~0.65) 35건 결판승률 20.8% < 중간 구간(0.60~0.63) 15건 40.0% — **단조성 역전**. ④ 오프라인 테이블 전역 승률 **0.2364**(258결판) vs 공표 P̂ 평균 0.634. ⑤ 보정 18셀 δ_eff **전부 음수**(−0.0396 ~ −0.7422), `BO\|RANGING\|CHOP`의 δ=−1.12, `p_prior_mean`=0.679 vs 실현 0.4545. ⑥ 축 IC: corr(L,R)=+0.075, corr(F,R)=−0.061, corr(C,R)=−0.205 → 세 가중치 모두 근거 없음. |
| **4. 제안하는 변경 방향** | 라이브는 계속 학습하지 않는다(5-B). **오프라인에서 prior 자체를 재적합**하고, 재적합된 prior + δ_eff를 라이브가 읽게 한다. 즉 "prior는 고정 신념" 가정을 폐기하고 "prior도 주기적으로 재발행되는 산출물"로 승격한다. |
| **5. 변경해야 할 알고리즘 로직** | **(a)** `analysis/calibrate.py`에 prior 재적합 단계 추가: 258+ 결판 후보에 대해 `tb_win ~ b0[setup] + wC·C + wL·L + wF·F` 로지스틱을 **purged-CV + 72h embargo**(기존 `WRF_EMBARGO_HOURS` 재사용)로 적합, 계수를 `calibration_table.json`의 신규 `prior` 블록으로 발행.<br>**(b)** `calibration._prior_logodds`가 `config` 상수 대신 **테이블의 prior 블록을 우선 소비**, 부재 시 현재 config 값으로 폴백(콜드스타트 안전).<br>**(c)** **IC가 0인 축은 가중치를 0으로 수축시킨다** — L·F는 현재 표본에서 무정보이므로 재적합이 자연히 0 근방으로 보낸다. 이것이 "가중치를 손으로 조정"보다 안전하다.<br>**(d) cap 재정의**: `WRF_PRIOR_CAP`(0.65)은 "과신 금지"용 상한이지만 지금은 **35건을 한 점에 묶는 정보 파괴 장치**다. cap을 확률 절단이 아니라 **사이징 절단**으로 이동 — P̂은 그대로 두고 `_size_from_p`에만 상한 적용.<br>**(e)** 재적합 prior가 OOS에서 단조성을 회복하면 `WRF_CALIB_DISABLED=false`로 δ_eff 경로 점등(5-I 단계 점등). |
| **6. 기대 효과** | P̂이 다시 순위정보를 가지면 floor(0.58)가 실제 필터로 작동한다. 현재 floor는 사실상 비구속(모든 후보가 0.584~0.650) — 재적합 후 다수 후보가 floor 아래로 내려가면 **개선안 1·5가 손대지 못하는 잔여 FP도 자동 제거**된다. 사이징도 정상화. |
| **7. 부작용 / 위험** | ① 재적합 prior가 대부분을 floor 아래로 보내면 **발사 빈도가 급감**한다(목적함수 N 붕괴). 완화: floor를 함께 재검토하되, 승률 플로어를 낮추는 것은 설계 철학 위반이므로 **유니버스·셋업 확장으로 N을 회복**(5-A). ② 258결판은 대부분 CHOP/RANGING 단일 레짐 — UPLEG 표본이 없어 재적합 계수가 레짐 편향을 그대로 흡수한다. ③ cap을 사이징으로 옮기면 P̂ 표기값이 커져 사람이 과신할 수 있다(문서화 필요). |
| **8. 과적합 가능성** | **높음** — 여기가 가장 위험한 개선안이다. 258결판에 3계수+6절편을 적합하는 것은 자유도가 크다. 완화: ① purged-CV + embargo 필수, ② 계수에 강한 정규화(ridge) 적용, ③ **부호 제약**(w ≥ 0)을 걸어 축의 의미론 반전을 금지, ④ 절편은 셋업별로만 두고 셀별 조정은 기존 δ_eff 수축 경로에 위임, ⑤ **OOS 구간을 미리 잘라두고(예: 최근 30% 홀드아웃) 적합에 절대 쓰지 않는다.** |
| **9. 검증 방법** | ① 홀드아웃에서 **reliability diagram**(예측 P̂ 10분위 vs 실현 승률) 단조성 + **Brier score / log-loss** 개선 확인. ② 현재 prior 대비 **AUC**가 홀드아웃에서 유의하게 상승하는지(0.5 근방이면 기각). ③ `backtest.py --ab`로 prior-vs-재적합 그림자 A/B를 최소 4주 라이브 병행 후 점등(5-I). ④ 발사수 변화를 반드시 함께 보고 — 승률만 오르고 N이 붕괴하면 기각. |

### 개선안 3 — 발사권 폐루프 복원: 방향별 fire-rights 점등 + 셀 희석 제거

| 항목 | 내용 |
|---|---|
| **1. 개선 대상** | `analysis/calibrate.py::_fire_rights` / 발사권 산출 블록, `src/config.py`(`WRF_FR_BY_DIR`, `WRF_FR_MIN_DECIDED`, `WRF_FR_DEMOTE_P`), `src/wrf/calibration.py::evaluate` |
| **2. 현재 문제** | "실현 승률로 나쁜 셀의 발사권을 뺏는다"는 거버넌스 장치가 **한 번도 발동한 적이 없다**. 강등 조건이 `n_fire_decided ≥ 8`인데, 28셀 중 이를 만족하는 셀이 1개뿐이다. 게다가 셀 단위 검정은 롱/숏을 섞어 희석한다 — 롱 +0.67 / 숏 −0.37을 평균 내면 어느 쪽도 강등되지 않는다. |
| **3. 데이터상 근거** | ① `calibration_table.json`: `n_shadow = 0`, `n_shadow_dir = 0`. ② `n_fire_decided` 분포: 최대 16(BO\|RANGING\|CHOP), 나머지 27셀 중 24셀이 **4 이하**, 12셀이 **0**. ③ 유일한 자격셀 BO\|RANGING\|CHOP의 P(WR≥floor)=**0.1859** — DEMOTE_P 0.15를 간발로 넘겨 생존. 그런데 이 셀의 라이브 실적은 BO SHORT −7.81R을 포함한다. ④ 셀 공간 = 6셋업 × 4레짐 × 3거시 = 72셀인데 6주 발사가 59건 → **셀당 연 7건 수준**, 강등까지 수년. ⑤ 방향 희석 실증: BO\|RANGING\|CHOP을 방향으로 쪼개면 LONG 7건 avgR +1.41 / SHORT 12건 avgR −0.57. |
| **4. 제안하는 변경 방향** | 셀 키를 늘리지 않고(5-H 준수) **이미 코드에 존재하나 꺼져 있는 방향분리 발사권을 점등**하고, 검정 모집단의 희소성을 **거시 차원 풀링**으로 해소한다. 예측 파라미터를 학습하는 게 아니라 발사권만 박탈/복권하므로 과적합 노출이 낮다. |
| **5. 변경해야 할 알고리즘 로직** | **(a)** `WRF_FR_BY_DIR=true` 점등. `calibrate.py`는 이미 `(cell, dir)`별 Beta-Binomial 사후검정과 히스테리시스를 구현해 두었고, `calibration.evaluate`도 `fire_rights_by_dir`를 읽는 경로가 있다 — **신규 로직 없이 배선만 연결**된다.<br>**(b) 검정 계층 추가**: 셀에 표본이 없으면 부모로 올라가 검정한다. 계층 = `(setup, dir)` → `(setup, regime_1h, dir)` → `(setup, regime_1h, btc_macro, dir)`. 가장 구체적이면서 `n_fire_decided ≥ MIN_DECIDED`를 만족하는 층에서 발사권을 발행. **δ 학습이 아니라 발사권만**이므로 셀 키 확장(5-H)에 해당하지 않는다.<br>**(c)** `WRF_FR_MIN_DECIDED`를 8 → 6으로 완화하되, 강등된 셋업은 섀도로 계속 기록·채점돼 **자동 복권 경로가 살아 있음**을 근거로 삼는다(오강등 비용은 일시적).<br>**(d)** 발사권 산출 모집단을 "발사 ∪ 격리-미발사"에서 **"발사분"으로 한정하는 현행 정책은 유지**(floor가 거부한 후보의 손실로 강등하지 않기 위함). |
| **6. 기대 효과** | 개선안 1·2·5가 놓친 나쁜 조합을 **사후적으로, 자동으로** 차단한다. 이번 사건(BR 강등 → BO SHORT가 빈도를 물려받음)의 재발 방지 — 새 셋업이 빈도를 차지하면 6~8결판 내에 판정이 난다. 사람이 매번 진단할 필요가 없어진다. |
| **7. 부작용 / 위험** | ① 소표본 오강등으로 좋은 조합이 일시적으로 죽는다(기회비용). ② 계층 검정에서 상위 층이 강등되면 하위 셀 전체가 함께 죽어 **N이 급감**할 수 있다 — 예: `(TF, long)` 강등 시 TF 롱 전면 중단. ③ 히스테리시스(복권 P≥0.50)가 비대칭이라 한 번 죽은 조합의 복귀가 느리다. |
| **8. 과적합 가능성** | **낮음**. 예측 계수를 적합하지 않고 사후검정으로 권한만 조정한다. 단 `MIN_DECIDED` 완화와 계층 추가는 **오강등률을 올린다** — 이는 과적합이 아니라 분산 문제이며, 자동 복권 경로가 완충한다. 주의점: 중첩 트레이드로 실효 표본이 명목보다 작으므로(`n_indep` 참조) `n_fire_decided`도 **stride 기반 독립 표본으로 세는 것**을 권한다. |
| **9. 검증 방법** | ① 과거 258결판을 시계열로 재생하며 **"만약 이 폐루프가 켜져 있었다면 언제 무엇이 강등됐을지"** 를 재구성(`analysis/audit/verify_fire_rights_replay.py` 신규). ② 강등 시점 이후의 실현 R을 합산해 **회피된 손실**을 정량화. ③ 동시에 **오강등으로 놓친 이익**도 함께 보고(양면 제시 — 한쪽만 보면 항상 좋아 보인다). ④ 강등 지연(첫 강등까지 걸린 결판 수) 분포를 보고 `MIN_DECIDED` 값을 결정 — 사후 최적화가 아니라 "지연 목표(예: 10결판 이내)"를 먼저 정하고 그에 맞춘다. |

### 개선안 4 — TP 기하 재설계: R-배수 고정 TP → 구조 TP ∧ MFE 분위 상한, TF 트레일 실집행

| 항목 | 내용 |
|---|---|
| **1. 개선 대상** | `src/wrf/levels.py::compute_levels` (TF/RV/BR 분기), `src/wrf/notion_wrf.py::_eval_signal`(청산 채점), `src/config.py`(`WRF_TF_TRAIL*`, 신규 TP 파라미터) |
| **2. 현재 문제** | ① TF/RV/BR의 TP는 구조가 아니라 `SL거리 × 고정 RR`이다(docstring은 "TP=측정이동/직전레벨"이라 하지만 코드는 상수 배수). 변동성이 커지면 SL이 넓어지고 TP는 그 2~2.5배로 더 멀어져 **도달 불가능해진다**. ② `_eval_signal`은 TP/SL/t_max만 본다 — **부분익절·본전스톱·MFE 기반 관리가 전무**. ③ TF에만 있는 `trail_dist`는 라이브 주석으로만 실리고 원장 채점에는 반영되지 않아 **라이브와 오프라인 채점 규칙이 갈린다**. |
| **3. 데이터상 근거** | ① TF의 TP 거리 = 진입가의 **6.4%(롱)~8.7%(숏)**, 그런데 TF 7건 평균 MFE는 **0.93R(≈3%)** — 7건 중 6건이 TP 근처도 못 갔다. ② 만기청산 16건: MFE 평균 **1.51R**, 13/16이 ≥1.0R, **2/16만 ≥2.0R**, 실현 R 평균 **+0.51**. TP는 2.0~2.5R에 있다. ③ SL 거리 3분위에서 넓은 SL 구간(3.02%)의 avgR −0.32 < 좁은 구간(1.19%)의 +0.47 — TP가 SL에 연동돼 함께 멀어진 결과. ④ 보수적 반사실: 비-SL 트레이드만 1.5R에서 청산 시 **+5.30R vs 기준 +4.08R**. ⑤ TP_HIT 13건의 평균 MFE 2.20R > 평균 RR 1.96 → **TP에 실제 도달한 건들은 TP가 적정했다**. 문제는 도달 못 한 쪽의 TP다. |
| **4. 제안하는 변경 방향** | TP를 "SL의 배수"에서 분리한다. **(i)** 셋업별로 구조 타깃을 우선 사용하고, **(ii)** 구조 타깃이 없거나 과도하면 **해당 셋업×심볼의 MFE 자기분포 상위 분위(예: p60~p70)** 로 상한을 건다(5-C: 절대 임계가 아니라 자기분포 백분위). **(iii)** TF는 고정 TP 대신 트레일을 **라이브·오프라인 동일 규칙으로 실집행**한다. |
| **5. 변경해야 할 알고리즘 로직** | **(a) TP 상한 도입** `compute_levels`의 TF/RV/BR 분기에서 `tp_dist = sl_dist × rr` 계산 후:<br>`tp_dist = min(tp_dist, mfe_p65_abs)` — `mfe_p65_abs`는 L1에서 산출한 **해당 심볼의 롤링 N봉 최대유리이동 분포 65분위 × ATR**. 코인·변동성에 자동 적응하고 튜닝 노브가 아니다.<br>**(b) 구조 TP 실제 배선** RV/BR은 docstring이 약속한 "직전 레벨"(주간레벨/스윙)을 실제로 소비하도록 배선 — 이미 `raw.weekly` / `df_1h` 스윙이 features에 있다.<br>**(c) TF 트레일 실집행** `_eval_signal`이 `trail_dist`를 소비해 `labels._trailing_barrier`와 **동일한 샹들리에 규칙**(초기 SL → HWM∓k·ATR 단조 래칫)으로 채점하도록 확장. 라이브·오프라인 규칙 일치가 목적이며, 라이브 봇은 여전히 상태를 들지 않는다(규칙만 발행 — 5-E 준수).<br>**(d)** RR·EV 게이트는 변경된 `tp_dist` 기준으로 재계산되므로, TP 상한이 낮아지면 RR이 떨어져 **일부 후보가 EV 게이트에서 자동 탈락**한다 — 개선안 1과 독립적으로 FP를 줄이는 부수 효과. |
| **6. 기대 효과** | 만기청산 16건(MFE 1.51R → 실현 0.51R)의 반납분 회수 ≈ **+1~2R/59건**. TF의 도달불가 TP 해소. 라이브·오프라인 채점 규칙 일치로 보정 데이터 품질 개선(현재 TF는 두 규칙이 달라 δ_eff가 오염돼 있을 수 있다). |
| **7. 부작용 / 위험** | ① TP를 당기면 **큰 승리(TP_HIT 13건 평균 MFE 2.20R)를 잘라낸다** — 반사실에서 1.0R·1.2R 상한이 오히려 기준보다 나빴던 이유가 정확히 이것이다. 상한을 너무 공격적으로 잡으면 손실이다. ② RR 하락 → EV 게이트 탈락 → 발사수 감소(N 감소). ③ 트레일 실집행은 t_max 72h와 결합해 **보유기간이 길어지고 자본 회전율이 떨어진다**. |
| **8. 과적합 가능성** | **중간**. MFE 분위(p65)가 튜닝 노브가 되면 59건에 과적합된다. 완화: ① 분위를 **하나만** 쓰고 셋업별로 다르게 두지 않는다, ② 분위 산출 윈도를 기존 `WRF_PCT_WINDOW`(200봉)와 공유해 신규 파라미터를 1개(분위값)로 제한, ③ 반사실 곡선(1.0/1.2/1.5/1.75R)이 **평평한 구간의 중앙**을 고르지 극댓값을 고르지 않는다. |
| **9. 검증 방법** | ① JSONL path 재생(`labels.triple_barrier`)으로 **TP 상한 스윕**을 하되, 결과 곡선의 형태(단봉인지, 어디가 평평한지)를 보고 **극댓값이 아니라 안정 구간**을 선택. ② 시간 2분할 + 심볼 3분할 모두에서 개선 부호가 유지되는지 확인. ③ TF 트레일은 `labels._trailing_barrier`로 채점한 결과와 고정 TP 채점 결과를 동일 후보집합에서 비교(A/B). ④ **큰 승리 손실분을 반드시 별도 보고** — 상한이 잘라낸 MFE의 총합을 명시하고 순효과로 판단. |

### 개선안 5 — Setup precond 복원 및 검증되지 않은 셋업의 섀도 강등 (RV soft 롤백 + TF 격리 + BO 방향 조건)

| 항목 | 내용 |
|---|---|
| **1. 개선 대상** | `src/config.py`(`WRF_RV_SOFT_PRECOND`, `WRF_RV_SOFT_MIN_CONFIRMS`, `WRF_SHADOW_SETUPS`, `WRF_BO_IN_RANGING`), `src/wrf/detectors.py::_detect_rv/_detect_bo`, `src/wrf/features.py::allowed_setups` |
| **2. 현재 문제** | ① RV의 하드 시퀀스(CHoCH → 리테스트 → 반전캔들)가 soft 모드에서 **L 감쇠로 대체**됐다. 감쇠 계수(0.82·0.90)는 P̂을 floor 아래로 못 내리므로 사실상 게이트가 사라졌다. ② TF는 라이브·오프라인 모두 승률이 붕괴했는데 발사권이 살아 있다. ③ BO는 `WRF_BO_IN_RANGING=true`로 RANGING까지 열려 있고 방향 조건이 없다. |
| **3. 데이터상 근거** | ① **RV**: 확인 3개 이상 9건 avgR **+0.87 / 승률 78%** vs 확인 2개 2건 avgR **−1.00 / 0%**. 시퀀스 "소진우위"(CHoCH·리테스트 둘 다 없음) 3건 **0승 3패, 전부 −1R**. ② **TF**: 라이브 7건 1승 6패(결판 0/5), 평균 MFE 0.93R, SL 71%. 오프라인 셀 `TF|RANGING|CHOP` **0/6**, `TF|SQUEEZE|CHOP` **0/3**, `TF|TRENDING|CHOP` **0/2** — **TRENDING 포함 전 레짐 0승**. 셋업 pooled WR **0.201로 6셋업 중 최저**. ③ **BO**: LONG 8건 +11.32R(SL 13%) vs SHORT 13건 −7.81R(SL 77%). RANGING 한정: LONG 7건 +1.41 avgR vs SHORT 12건 −0.57 avgR. RR>3인 6건 중 5건이 BO이며 그중 숏 4건 전부 SL_HIT(MAE 1.04~2.16). ④ 제거 반사실: BR+BO SHORT+TF 제외 시 20건 **+17.83R(avgR +0.89, 승률 75%)**. |
| **4. 제안하는 변경 방향** | 5-I(검증 → 점등)를 **원상복구**한다. 근거 없이 완화된 게이트는 되돌리고, 실적이 무너진 셋업은 BR과 동일하게 섀도로 강등해 **기록·채점은 유지하되 발사만 막는다**. 새 로직을 추가하는 게 아니라 이미 있는 거버넌스 장치를 적용하는 것이 핵심이다. |
| **5. 변경해야 할 알고리즘 로직** | **(a) RV soft 롤백**: `WRF_RV_SOFT_MIN_CONFIRMS` 2 → 3, 그리고 `_detect_rv`의 soft precond에 **`(choch ∨ retest)` 를 하드 요구로 복원**. 즉 soft 모드는 "CHoCH·리테스트 **둘 중 하나**는 필수, 나머지 하나는 L 감쇠"로 재정의 — 전면 롤백(둘 다 필수)보다 N 손실이 작으면서 0/3 코호트를 정확히 제거한다.<br>**(b) TF 섀도 강등**: `WRF_SHADOW_SETUPS`에 `TF` 추가(`"BR,TC,TF"`). 후보 생성·기록·오프라인 채점은 계속되므로 개선안 4의 트레일 재설계 효과를 섀도 표본으로 검증한 뒤 복권한다.<br>**(c) BO 방향 조건**: `_detect_bo`에 방향 대칭 precond 추가 — 돌파 방향이 **4H 레짐/구조와 정합**할 것. 구체적으로 `regime_4h == "RANGING"` 이면서 `raw.ema_4h`가 돌파 방향과 반대이면 후보를 만들지 않는다. 롱/숏 부호만 반전한 완전 대칭(5-D). 대안(더 보수적): `WRF_BO_IN_RANGING=false`로 되돌려 BO를 SQUEEZE/EXPLOSIVE 출발로 한정. **둘 중 하나만 선택**하고 동시 적용하지 않는다(교락 방지). |
| **6. 기대 효과** | 데이터가 직접 지목한 손실 코호트(RV 소진우위 −3R, TF −3.81R, BO SHORT −7.81R)를 제거. 세 조치의 합은 반사실 기준 **−14.6R의 손실 제거**이며, 남는 20건의 avgR은 +0.89. 개선안 1~4가 미작동해도 즉시 효과가 나는 **가장 낮은 리스크의 조치**다. |
| **7. 부작용 / 위험** | ① **신호 빈도가 절반 이하로 줄어든다** — 59건 → 20~35건. 목적함수 5-A(max N)의 직접 위반이며, 유니버스 확장으로 N을 회복해야 한다. ② TF 섀도 강등은 "추세추종 부재" 상태를 만든다 — 진짜 추세장이 오면 전 셋업이 반전형이라 대응 불가. ③ RV 게이트 강화는 6월의 성공 코호트(확인 3, +5.82R)를 건드리지 않지만, 임계 근처 후보를 잃는다. ④ 셋업 제거는 다시 "빈 자리를 누가 채우는가" 문제를 만든다 — **개선안 3(발사권 폐루프)과 반드시 함께 가야 한다.** |
| **8. 과적합 가능성** | ① RV 롤백: **낮음**. 완화된 게이트를 원상복구하는 것이고, 원래 게이트는 이 데이터 이전에 설계됐다. 0/3은 소표본이지만 방향이 "원설계 복귀"라 자유도를 늘리지 않는다. ② TF 섀도: **낮음**. 라이브 0/5 + 오프라인 0/11 = 독립 두 표본에서 일관, 그리고 섀도는 되돌리기 가능한 최소 개입이다. ③ BO 방향 조건: **중간**. "4H EMA 정합"은 새 조건이고 13건 숏에 맞춰 고른 것처럼 보일 수 있다 — 그래서 대안(BO_IN_RANGING 롤백, 자유도 0)을 함께 제시했고 **둘 중 자유도가 낮은 쪽을 우선**한다. |
| **9. 검증 방법** | ① 258결판 후보 데이터셋에서 각 조치를 **개별로** 적용해 발사집합의 승률·평균R·발사수를 산출(동시 적용 금지 — 교락). ② RV: 확인수 2 vs 3 vs 4의 승률 곡선을 시간 2분할로 확인, 단조성이 양 구간에서 유지되는지 검사. ③ TF: 섀도 강등 후 최소 30결판 축적 → 개선안 4의 트레일 규칙으로 재채점해 복권 여부 판정(Gate-Out 사전 정의: 트레일 채점 승률 ≥ floor). ④ BO: 두 대안(4H 정합 조건 vs BO_IN_RANGING 롤백)의 발사수·승률을 나란히 보고하고 **발사수 손실 대비 승률 개선 효율**이 높은 쪽 선택. ⑤ 모든 조치에 대해 **BTC초과수익(exret_24h) 기준 재검증** — 롱 편향 시장에서 원시수익만 보면 착시가 생긴다. |

## 7. Recommended Algorithm Architecture

개선 후 흐름 (변경점 **굵게**):

```
L1  MEASURE  (features.build_features)
    raw / pct(자기분포 백분위)
    ★ pct["drift"]     = (close − close[−42]) / ATR 의 200봉 자기분포 백분위   [개선1]
    ★ mfe_p65_abs      = 심볼 롤링 MFE 분포 65분위 × ATR                        [개선4]
    ctx{regime_1h, regime_4h, bias_1d, btc_macro, allowed_setups}

L2  DETECT   (detectors.detect_all)
    TF ─ ★ WRF_SHADOW_SETUPS 로 섀도 강등 (후보·기록 유지, 발사 차단)          [개선5b]
    BO ─ ★ 4H 구조 정합 precond (또는 BO_IN_RANGING 롤백) — 롱/숏 대칭        [개선5c]
    RV ─ ★ soft precond: (CHoCH ∨ 리테스트) 하드 필수 + confirms ≥ 3          [개선5a]
    MR / BR(섀도) / TC(섀도) — 변경 없음
    Regime Routing — 변경 없음

L4' LEVELS   (levels.compute_levels)
    SL : 현행 유지 (구조 SL + ATR 쿠션 + 1.2~5% 클램프) — 근거 불충분, 변경 보류
    TP : ★ 구조 타깃(주간레벨/박스/스윙) 우선
         ★ tp_dist = min(구조타깃거리, mfe_p65_abs)                            [개선4a]
    TF : ★ 트레일(HWM ∓ 3·ATR) 규칙 발행 — 라이브·오프라인 동일 채점          [개선4c]
    rr = |tp − entry| / sl_dist   ← TP 상한 반영분 자동 축소

L3  PROBABILITY  (calibration.evaluate)
    ★ prior 계수를 config 상수가 아니라 calibration_table.prior 블록에서 로드   [개선2a/2b]
       (오프라인 purged-CV 재적합 · 부재 시 config 폴백)
    p_prior = σ(b0[setup] + wC·C + wL·L + wF·F − λ·min_axis_penalty)
    ★ cap 은 확률이 아니라 사이징에만 적용                                      [개선2d]
    p_cal   = σ(prior_logodds + δ_eff[cell])
    ★ WRF_CALIB_DISABLED=false (OOS 단조성 검증 통과 후 점등)                   [개선2e]
    ★ fire_rights = 계층 검정 (setup,dir) → (setup,regime,dir) → (cell,dir)     [개선3]
       WRF_FR_BY_DIR = true

L0  VETO
    ① 스프레드  ② 청산 캐스케이드  ③ 데이터 신선도
    ④ MACRO_HEADON (btc_macro, RV/BR 면제)  — 유지
    ★ ⑤ DRIFT_HEADON: (long ∧ pct.drift ≤ LO) ∨ (short ∧ pct.drift ≥ HI)      [개선1b]
         반전 셋업은 극단 백분위에만 적용 (면제 아님)                            [개선1c]

L4  FIRE
    EV = P̂·RR − (1−P̂) ≥ 0.15  ∧  RR ≥ 0.85
    quarantine = SHADOW_SETUP(BR,TC,★TF) ∨ ★fire_rights_by_dir == 'shadow'
    fire = P̂ ≥ floor(0.58) ∧ ¬VETO ∧ EV ∧ ¬quarantine
    size = min(cap_size, base + (smax−base)·(P̂−floor)/(1−floor))

OFFLINE  (analysis/calibrate.py — 주간)
    후보 전량 → triple_barrier / trailing_barrier 채점
    ★ ① prior 계수 재적합 (purged-CV + 72h embargo + ridge + 부호제약)          [개선2a]
      ② δ_eff 부분풀링 (현행 유지)
    ★ ③ 발사권: 계층 · 방향분리 · 독립표본 기준 n_fire                          [개선3b/3d]
    → calibration_table.json 발행 (라이브는 읽기만 — 5-B 불변)
```

**설계 원칙 준수 확인**
- 5-B 라이브 무학습: 재적합·발사권 모두 오프라인. 라이브는 테이블 읽기만. ✅
- 5-C 백분위 상대평가: 신규 피처(drift, mfe_p65) 모두 자기분포 백분위. ✅
- 5-D 롱/숏 대칭: DRIFT_HEADON·BO 정합 조건 모두 부호 반전 대칭. 방향 분리는 **발사권(사후 거버넌스)에서만** 발생하고 디텍터·피처는 대칭 유지. ✅
- 5-E 무상태: 트레일은 규칙 발행 + 오프라인 채점. 라이브 상태 없음. ✅
- 5-H 셀 키 불변: `(setup × regime_1h × btc_macro)` 유지. 방향은 **δ 학습 키가 아니라 발사권 검정 축**으로만 분리. ✅
- 5-J 합산 점수 금지: 새 보너스/패널티 없음. 판정은 여전히 `P̂ ≥ floor`. TP 상한은 기하 제약이지 점수가 아니다. ✅
- 5-K 파라미터: 신규 실질 노브 = `WRF_DRIFT_LO/HI`(1쌍, 기존 극단컷 값 재사용), `WRF_TP_MFE_Q`(1개), `WRF_FR_MIN_DECIDED`(기존). **신규 순증 2개.** ✅

## 8. Implementation Plan

각 단계는 **기본 OFF 토글로 출시 → 사전등록 검증 → 점등**(5-I). 단계 간 교락을 막기 위해 **한 번에 하나만 점등**한다.

### Phase 0 — 검증 인프라 (코드 변경 전, 필수)
1. `analysis/audit/replay_gate.py` 신규: JSONL v3 후보 전량에 임의 게이트 함수를 적용해 **(발사수, 승률, 평균R, exret 기준 평균R)** 을 시간 2분할·방향별로 출력하는 공용 하네스.
   - 검증: 게이트를 항등함수로 주면 현재 발사집합 통계가 재현될 것.
2. 최근 30% 구간을 **홀드아웃으로 봉인**하고 이후 모든 적합에서 제외하는 규약을 스크립트에 박제.
   - 검증: 적합 스크립트가 홀드아웃 행을 읽으면 assert 실패.

### Phase 1 — 개선안 5 (즉시, 최저 리스크)
3. RV soft precond 복원 (`(choch ∨ retest)` 필수 + confirms ≥ 3). 토글 `WRF_RV_SOFT_REQUIRE_STRUCT`(기본 OFF).
   - 검증: replay_gate에서 확인수 2 코호트가 사라지고, 확인수 3 코호트 통계가 불변.
4. TF를 `WRF_SHADOW_SETUPS`에 추가.
   - 검증: 라이브 발사 로그에 TF fire=true가 0건, JSONL 후보에는 TF가 계속 기록됨.
5. BO 방향 조건 — **자유도 0 대안(`WRF_BO_IN_RANGING=false`)을 먼저** 시도.
   - 검증: replay_gate에서 BO SHORT×RANGING 12건이 제거되고 BO LONG×RANGING 7건의 처리 여부를 명시적으로 확인(둘 다 사라지면 순효과 재계산).
   → **Gate-Out**: 4주 라이브에서 발사집합 avgR이 직전 4주 대비 개선, 발사수 ≥ 15건/4주.

### Phase 2 — 개선안 3 (거버넌스 폐루프, 신규 예측 로직 없음)
6. `analysis/audit/verify_fire_rights_replay.py`: 과거 결판을 시계열 재생해 강등 시점·회피 손실·오강등 기회비용을 양면 보고.
   - 검증: 재생 결과가 현재 테이블의 `fire_rights`(전부 live)를 재현할 것(항등 케이스).
7. 계층 검정 + 독립표본 카운트를 `calibrate.py`에 추가, `WRF_FR_BY_DIR=true` 점등.
   - 검증: 다음 주간 잡에서 `n_shadow_dir > 0`이고, 강등 대상이 replay 예측과 일치.
   → **Gate-Out**: 강등 지연(첫 강등까지 결판 수) 중앙값 ≤ 10.

### Phase 3 — 개선안 1 (방향 게이트)
8. L1에 `pct["drift"]` 계측 추가 (**게이트 미연결 — 기록만**).
   - 검증: JSONL에 drift 백분위가 실리고 분포가 [0,1] 균등에 가까움.
9. 2주 이상 계측 축적 후 `WRF_DRIFT_VETO` 점등 판단. 점등 전 replay_gate로 258결판 재검.
   - 검증: 방향별·시간 2분할·exret 기준 모두에서 개선 부호 일관. 하나라도 반대면 보류.
   → **Gate-Out**: ETH SHORT류(상승 드리프트 역행) 코호트의 발사가 실측으로 사라짐.

### Phase 4 — 개선안 4 (TP 기하)
10. L1에 `mfe_p65_abs` 계측 추가 (기록만).
11. `_eval_signal`에 트레일 채점 배선 — **먼저 오프라인 라벨러와 결과 일치를 검증**(동일 후보에 대해 두 구현의 outcome이 100% 일치해야 함).
12. TP 상한 적용 (`WRF_TP_MFE_CAP`, 기본 OFF) → 스윕 곡선의 **평평한 구간 중앙**을 선택해 점등.
   - 검증: 큰 승리 절단분(잘라낸 MFE 총합)을 별도 보고, 순효과가 시간 2분할 모두에서 양수.

### Phase 5 — 개선안 2 (P̂ 재보정, 최고 위험 · 최후)
13. `calibrate.py`에 prior 재적합 블록 추가, `calibration.py`가 테이블 prior를 우선 소비 (**출시 시 테이블에 prior 블록 미발행 → 현행 config 폴백 = 무변경**).
14. 홀드아웃에서 reliability diagram·Brier·AUC 산출. 단조성 회복 실패 시 **여기서 중단**.
15. `backtest.py --ab`로 최소 4주 그림자 병행 → 우위 입증 후 prior 블록 발행 + `WRF_CALIB_DISABLED=false`.
16. cap의 사이징 이관은 **가장 마지막** (P̂ 표기 의미가 바뀌므로 README·Notion 스키마 문서 동시 갱신).
   → **Gate-Out**: 홀드아웃 Brier 개선 ∧ 발사수 감소율 ≤ 40%.

### 되돌리기
모든 단계가 환경변수 1개 토글로 즉시 원복 가능하며, Phase 간 의존이 없다(Phase 3·4·5는 서로 독립). Phase 1과 Phase 2는 **함께 유지**해야 한다 — Phase 1의 셋업 제거가 만드는 빈도 공백을 Phase 2의 폐루프가 감시하기 때문이다.

## 부록 B — 이번 분석에서 확인하지 못한 것 (후속 필요)

1. **SL을 넓혔다면 회복했는가** — CSV는 SL 히트 시점에서 경로가 잘린다. JSONL `path` 재생 필요.
2. **C축의 음의 IC가 TF 교락인지 진짜인지** — TF 격리(Phase 1) 후 재측정해야 판정 가능.
